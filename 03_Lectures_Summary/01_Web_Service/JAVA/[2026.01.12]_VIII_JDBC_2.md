# Java DataBase Connectivity II

기존의 단순한 연동 방식에서 벗어나, 실무에서 사용하는 MVC 패턴과 DAO/DTO 구조를 적용하여 코드의 재사용성을 높인 단계입니다.

## 0. 아키텍처

| 구성 요소 | 역할 및 특징 |
| --- | --- |
| DTO (DeptDTO) | DB Table과 매칭되는 데이터 전송 객체입니다. 목적 및 보안에 따라 엔티티와 분리하여 운영하는 것이 좋습니다 |
| Util (DBUtil) | Connection 생성, 자원 반환 등 공통 모듈을 관리합니다. |
| DAO (DeptDAO) | 실제 DB 연동 로직만 전담하는 객체입니다. |
| Controller | 클라이언트의 요청을 받아 적절한 모델을 호출하고, 결과에 따라 출력 View를 지정합니다. |

    * 구현 단계: 드라이버 로딩 ➔ DB 접속 ➔ SQL 작업 ➔ 결과 활용 ➔ 접속 해제.

    * 프로그램 관점: `DriverManager`를 통한 `Connection` 획득, `Statement`를 통한 SQL 실행, `ResultSet`으로 결과 처리 후 역순(RS ➔ Stmt ➔ Con)으로 자원 반환(close).

    * 재사용성 및 효율성: 중복 코드는 DBUtil로 분리하고, 드라이버 로딩은 `static{}` 블록을 통해 서버 기동 시 1회만 실행하며, 접속 정보는 `.properties` 파일로 관리하여 유지보수성을 높입니다.

## 2. DBUtil: 공통 기능의 모듈화

모든 DAO에서 공통으로 사용하는 드라이버 로딩, 접속, 자원 반환 로직을 별도로 분리한 클래스입니다.

### 2.1 DB 연결 로직

```Java
private static Properties dbinfo = new Properties();

// 드라이버 로딩은 서버 실행 시 단 1회만 수행
static {
    try {
        dbinfo.load(new FileInputStream("resources/dbinfo.properties"));
        Class.forName(dbinfo.getProperty("jdbc.driver"));
    }
    catch (Exception e) {
        e.printStackTrace();
    }
}

// 설정 파일에서 읽어온 정보로 접속 객체 생성
public static Connection getConnection() throws SQLException {
    return DriverManager.getConnection(dbinfo.getProperty("jdbc.url"),
                                       dbinfo.getProperty("jdbc.user"),
                                       dbinfo.getProperty("jdbc.pw"));
}
```

### 2.2 자원 반환 로직

```java
//DML - INSERT / UPDATE / DELETE
// 필요 자바 객체 - Connection / Statement
public static void close(Connection con, Statement stmt) {
    try {
        if(stmt != null) {
            stmt.close();
            stmt = null;
        }
        if(con != null) {
            con.close();
            con = null;
        }
    }
    catch (SQLException e) {
        e.printStackTrace();
    }
}

//DQL - SELECT
// 필요 자바 객체 - Connection / Statement / ResultSet
public static void close(Connection con, Statement stmt, ResultSet rs) {
    try {
        if(rs != null) {
            rs.close();
            rs = null;
        }
        // 중복 코드 제거를 위해 기존 close() 호출
        close(con, stmt);
    }
    catch (SQLException e) {
        e.printStackTrace();
    }
}
```

## 3. DAO (Data Access Object): DB 전담 처리

| 기술 요소 | 상세 설명 |
| --- | --- |
| `PreparedStatement` | SQL을 미리 컴파일하여 DB에 보냄으로써 반복 실행 시 속도가 빠르고, SQL Injection 공격을 방어하는 데 유리함. |
| `Statement` | 매 실행 시마다 SQL 문법 검증 ➔ 컴파일 ➔ 실행 과정을 반복하므로 상대적으로 비효율적임 |
| Exception Handling | DB의 예외를 Java에서 일괄 처리하며, 심각한 에러 발생 시 프로그램을 중지시키지 않고 사용자에게 재시도를 유도하도록 예외를 다시 던짐 |
| 다형성 활용 | 예외 처리 시 Exception 타입으로 선언하여 하위의 모든 예외 상황을 수용할 수 있게 설계함 | 

### 3.1 모든 부서 검색

```Java
public static ArrayList<DeptDTO> deptAll() throws SQLException {
    Connection con = null;
    Statement stmt = null;
    ResultSet rs = null;
    ArrayList<DeptDTO> allDept = null;
    
    try {
        con = DBUtil.getConnection();
        stmt = con.createStatement(); // DQL 실행을 위한 Statement 생성
        rs = stmt.executeQuery("SELECT * FROM dept");

        allDept = new ArrayList<DeptDTO>();
        while (rs.next()) { // 결과 집합을 DTO 객체로 변환하여 리스트에 추가
            allDept.add(new DeptDTO(rs.getInt("deptno"),
                                    rs.getString("dname"),
                                    rs.getString("loc")));
        }
    }
    catch (SQLException e) {
        // 호출한 Controller에게 예외 처리를 위임
        e.printStackTrace();
        throw e; 
    }
    finally {
        // 자원 반환
        DBUtil.close(con, stmt, rs);
    }
    return allDept;
}
```

### 3.2 새로운 부서 저장

보안과 성능이 우수한 `PreparedStatement`를 활용하여 데이터를 저장합니다.

```Java
public static boolean insertDept(DeptDTO dept) throws SQLException {
    Connection con = null;
    PreparedStatement pstmt = null;

    try {
        con = DBUtil.getConnection();
        // SQL 문법 검증 및 컴파일을 미리 수행하여 성능/보안성 향상
        pstmt = con.prepareStatement("INSERT INTO dept VALUES (?, ?, ?)");
        
        // 데이터 부분은 ? 표기 후 실행 직전에 값 대입
        pstmt.setInt(1, dept.getDeptno());
        pstmt.setString(2, dept.getDname());
        pstmt.setString(3, dept.getLoc());
        
        // 영향을 미친 행 수 반환 (1: 성공)
        int result = pstmt.executeUpdate();
        if (result == 1) return true;
    }
    catch (SQLException e) {
        e.printStackTrace();
        throw new SQLException("추가시 실패 재확인 후 재시도 요청합니다");
    }
    finally {
        DBUtil.close(con, pstmt);
    }
    return false;
}
```

### 3.3 특정 부서 정보 수정

입력된 데이터의 유무에 따라 SQL을 유연하게 선택하는 동적 쿼리 로직이 포함되어 있습니다.

```Java
public static boolean updateDept(DeptDTO dept) throws Exception {
    Connection con = null;
    PreparedStatement pstmt = null;

    // 데이터 존재 여부 확인 (동적 쿼리 구성을 위한 로직)
    String dname = dept.getDname();
    String loc = dept.getLoc();
    boolean hasDname = dname != null && !dname.equals("");
    boolean hasLoc = loc != null && !loc.equals("");

    try {
        con = DBUtil.getConnection();
        
        // 부서명, 지역 동시 수정
        if (hasDname && hasLoc) {
            pstmt = con.prepareStatement("UPDATE dept SET dname = ?, loc = ? WHERE deptno = ?");
            pstmt.setString(1, dname);
            pstmt.setString(2, loc);
            pstmt.setInt(3, dept.getDeptno());
        }
        // 부서명만 수정
        else if (hasDname) {
            pstmt = con.prepareStatement("UPDATE dept SET dname = ? WHERE deptno = ?");
            pstmt.setString(1, dname);
            pstmt.setInt(2, dept.getDeptno());
        }
        // 지역만 수정
        else if (hasLoc) {
            pstmt = con.prepareStatement("UPDATE dept SET loc = ? WHERE deptno = ?");
            pstmt.setString(1, loc);
            pstmt.setInt(2, dept.getDeptno());
        }
        else {
            throw new Exception("수정할 내용이 없습니다");
        }

        // 수정 성공 여부 반환
        return pstmt.executeUpdate() == 1;
    }
    catch (SQLException e) {
        e.printStackTrace();
        throw new Exception("수정시 실패 재확인 후 재시도 요청합니다");
    }
    finally {
        DBUtil.close(con, pstmt);
    }
}
```

## 4. Controller: 요청 제어 및 View 지정

요청 번호를 분석하여 적절한 비즈니스 로직을 호출하고, 그 결과에 따라 사용자에게 보여줄 화면을 결정하는 MVC 패턴의 핵심 제어 장치입니다.

```Java
public class DeptController {
    /**
     * 단순 요청 처리 (데이터 미포함)
     * reqNo 1: 모든 부서 정보 검색
     */
    public static void reqRes(int reqNo) {
        if (reqNo == 1) { 
            try {
                // DAO를 통해 전체 데이터를 가져와 성공 View로 전달
                DeptSuccessView.allDeptView(DeptDAO.deptAll());
            } catch (SQLException e) {
                // 검색 실패 시 사용자에게 재시도 안내
                DeptFailView.printMsg("모든 부서 검색 실패, 재시도 해주세요");
                e.printStackTrace();
            }
        } else {
            // DTO가 필요한 요청인데 번호만 전달된 경우 처리
            DeptFailView.printMsg("해당 요청 번호는 DeptDTO 데이터가 필요합니다");
        }
    }
    /**
     * 데이터 기반 요청 처리 (DTO 포함)
     * reqNo 2: 새로운 부서 저장
     * reqNo 3: 특정 부서 정보 수정
     */
    public static void reqRes(int reqNo, DeptDTO deptData) {
        // 검색 요청인 경우 데이터 없는 메서드로 토스
        if (reqNo == 1) { 
            reqRes(1);
        } 
        // 부서 저장 로직
        else if (reqNo == 2) {
            try {
                boolean r = DeptDAO.insertDept(deptData);
                // 추가 성공 시
                if (r) {
                    DeptSuccessView.successView(deptData.getDeptno() + "번 부서 추가 성공");
                }
                // 정상 실행되었으나 로직상 추가 불가(중복 등)
                else {
                    DeptSuccessView.successView("요청하신 부서번호가 이미 존재합니다. 확인 후 재시도...");
                }
            }
            catch (Exception e) {
                // 비정상 실행(예외) 시 메시지 출력
                DeptFailView.printMsg(e.getMessage());
                e.printStackTrace();
            }
        } 
        // 부서 수정 로직
        else if (reqNo == 3) {
            try {
                boolean r = DeptDAO.updateDept(deptData);
                // 수정 성공 시
                if (r) {
                    DeptSuccessView.successView(deptData.getDeptno() + "번 부서 수정 성공");
                }
                // 대상 부서가 없는 경우
                else {
                    DeptSuccessView.successView("요청하신 부서번호가 존재하지 않습니다. 확인 후 재시도...");
                }
            }
            catch (Exception e) {
                // 예외 발생 시 FailView로 에러 내용 전달
                DeptFailView.printMsg(e.getMessage());
                e.printStackTrace();
            }
        }
    }
}
```
