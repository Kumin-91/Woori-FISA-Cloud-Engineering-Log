# Web Components Day 01

## 1. HTML 문서 생성 및 서버 확인

* 디렉토리 구조: `src/main/webapp` 폴더는 웹 어플리케이션의 Root (/) 경로로 매핑됩니다. 서버 작동 확인을 위해 해당 폴더에 `index.html`을 작성합니다.

* 서버 배포: `Run As` → `Run on Server`를 선택하여 Tomcat 서버에 프로젝트를 적재합니다.

* 접속 주소: http://localhost:8080/step01_basic/index.html

    * Context Root: URL 주소에서 호스트와 포트 뒤에 오는 step01_basic 부분입니다. (일반적으로 프로젝트 이름과 동일하게 설정됩니다.)

    * Welcome File: 서버 설정에 따라 index.html은 파일명을 생략하고 입력해도 자동으로 호출됩니다.

## 2. Servlet

Java를 사용하여 동적인 웹 콘텐츠를 생성하는 서버 측 프로그램입니다.

### 2.1 서블릿 생성 및 매핑

* 생성: `New` → `Servlet`을 통해 클래스를 생성합니다.

* URL Mapping: 생성 과정 중 URL mappings 설정에서 클라이언트가 접속할 경로 (예: /ce)를 지정합니다.

    * 이는 코드 상단에 `@WebServlet("/경로")` 어노테이션으로 자동 반영됩니다.

* 기본 구조: 생성자와 함께 클라이언트의 전송 방식에 따라 `doGet` 또는 `doPost` 메서드가 자동으로 생성됩니다.

### 2.2 클라이언트 데이터 수집 및 처리

* HTML의 `<form>` 태그 등을 통해 전달된 데이터는 `HttpServletRequest` 객체를 통해 가져옵니다.

* 데이터 추출: `request.getParameter("name속성값")`을 사용하여 사용자가 입력한 id, pw 등을 받아옵니다.

* 출력: 받아온 값을 `System.out.println()`으로 콘솔에 출력하여 데이터 전달 여부를 확인합니다.

### 2.3 서블릿의 동작 원리

* 개발자가 직접 객체를 생성하지 않고 Tomcat이 서블릿의 생명주기를 관리하며 객체를 생성하고 메서드를 호출합니다.

* 싱글톤 (Singleton)

* 호출 시점

    * 클라이언트 (브라우저)가 매핑된 URL로 요청을 보냅니다.

    * 컨테이너는 해당 서블릿이 메모리에 있는지 확인합니다.

    * 처음 호출되는 것이라면 객체를 생성하고 `init()`을 실행합니다.

    * 이후 `service()` 메서드를 통해 요청 방식에 맞는 `doGet()` 또는 `doPost()`를 실행합니다.

### 2.4 전송 방식에 따른 차이 (GET vs POST)

| 구분 | GET 방식	| POST 방식 |
| --- | --- | --- |
| 호출 시점	| 주소창 직접 입력, `<a>` 태그 클릭, `<form>` 기본값 | `<form method="post">`로 명시적 설정 시 |
| 데이터 노출 | URL 뒤에 쿼리 스트링 (?id=...&pw=...)으로 노출 | 웹 쿼리 스트링이 은닉된 상태로 서버에 전송 |
| 보안 및 용도 | 보안 미고려, 즐겨찾기 및 검색용으로 주로 사용 | 보안이 필요한 ID/PW 전송, 서버 데이터 저장/수정 시 필수 |

### 2.5 브라우저 응답 처리 (Response)

```Java
// MIME 타입 설정
response.setContentType("text/html;charset=UTF-8");
// 출력 객체 활용
PrintWriter out = response.getWriter();
out.println(request.getParameter("name"));
out.println("<img src='images/sample.png'/>");
out.close();
```
