## 2. JPA 특징

* JPA는 자바와 RDBMS 사이의 패러다임 불일치를 해결해주는 ORM (Object-Relational Mapping) 표준 기술입니다.

* SQL 자동 생성 및 실행: 개발자가 객체를 조작하면 JPA가 적절한 SQL을 대신 생성하여 실행합니다.

* 참고: SQL 문장 개발 방법

    * JDBC

    * MyBatis (XML, SQL, Annotation)

    * JPA (XML, Annotation)

    * Spring Data JPA: JPA 기반으로 추상화

* 주의사항: SQL 자체에 튜닝이 필요한 경우 JPA 사용 고려

## 3. 구조

### 3.1 RDBMS의 Table과 매핑되는 Entity 클래스

Entity는 데이터베이스의 테이블과 1:1로 매핑되는 자바 객체입니다.

* 매핑 규칙

    * 클래스명 = 테이블명
    
    * 멤버변수 = 컬럼명

* 특징: 단순한 데이터 저장소가 아니라, 데이터베이스의 상태를 관리하는 핵심 객체입니다.

### 3.2 Entity와 DTO의 용도 분리

* 1. Entity: DAO와 DB사이에서 사용

    ```Java
    @Entity // JPA 관리 대상임을 선언 (생략 시 매핑 불가)
    public class Dept {
        @Id // PK(Primary Key) 설정 - JPA의 필수 제약 사항
        private int deptno;
        private String dname;
        private String loc;
    }
    ```

    * 데이터베이스 세부 사항을 캡슐화하며, 실제 DB 스키마와 직접 연결됩니다.

* 2. DTO: DAO, Service, Controller, Vieww 등등에서 사용

    ```Java
    // 테이블 구조와 상관없이 화면 요구사항에 맞게 필드 구성 가능
    public class Dept { 
        private int deptno;
        private String dname;
        private String loc;
    }
    ```

    * 레이어 사이에서 데이터를 전달하는 역할입니다.

## 6. JPA 동작 분석

### 6.1 `INSERT`: 저장 완료

```Java
Member m1 = new Member();
m1.setName("연아");
em.persist(m1);

tx.commit();
```

### 6.2 `INSERT` -> `UPDATE` : 재석이란 이름으로 저장 및 수정 완료

```Java
Member m1 = new Member();
m1.setName("연아");
em.persist(m1);

m1.setName("재석"); //추가
tx.commit();
```

### 6.3 `INSERT` 문장은 콘솔에 출력 단, DB에 실저장 불가

```Java
Member m1 = new Member();
m1.setName("연아");
em.persist(m1);

m1.setName("재석");
    //tx.commit(); //삭제
```

* SQL 최적화: 데이터가 새롭게 추가될 때는 `INSERT`를 생성하지만, 기존 데이터에 변경 사항이 없으면 불필요한 `UPDATE` 문은 생성하지 않습니다.

* 효율성 중심의 상태 관리: JPA는 엔티티의 생명 주기 (저장, 수정, 삭제 등)를 실시간으로 추적하며, 수정이 필요한 시점을 지능적으로 파악하여 DB와의 통신을 최소화합니다.

* 영속성 컨텍스트 활용: 엔티티의 최초 상태 (스냅샷)와 현재 상태를 비교하여 실제 변경이 일어난 경우에만 영구 저장 (`Commit`) 프로세스를 가동합니다.

## 7. Persistence Context

* 1차 캐시 및 동일성 보장:

    * 영속성 컨텍스트 내부의 1차 캐시에 엔티티를 보관하며, 엔티티의 고유 ID(@Id)를 키로 객체를 구분합니다.

    * 동일한 ID로 조회 시 항상 같은 객체 인스턴스를 반환하여 객체 동일성(a == b)을 보장합니다.

* 쓰기 지연 (Transactional Write-behind):

    * 객체를 저장하거나 수정할 때 즉시 DB에 SQL을 실행하지 않고, 내부 SQL 저장소에 모아둡니다.

    * 트랜잭션이 `Commit`되는 시점에 모아둔 SQL 문장들을 DB에 한꺼번에 실행하여 네트워크 비용을 최적화합니다.

* 변경 감지 (Dirty Checking)와 스냅샷:

    * 스냅샷 (Snapshot): 엔티티가 영속성 컨텍스트에 처음 들어온 시점의 상태를 복사해서 보관합니다.

    * 플러시 (Flush) 시점: 현재 엔티티의 상태와 스냅샷을 비교하여 변경 사항을 감지합니다.

    * 값이 수정되었다면 자동으로 `UPDATE` SQL을 생성하여 DB에 반영합니다.

## 8. 코드 예제

* Entity

    ```Java
    @Entity //entity라는 명시, 생략 불가, DTO엔 사용 금지!!!
    @Table(name = "member")
    @Getter
    @Setter
    @ToString //확인용으로 개발자가 ai제시한 코드 대비 수정
    public class Member {

        @Id //pk, null 불허, 중복 불허/Entity 객체들 구분용 고유한 id
        @GeneratedValue(strategy = GenerationType.IDENTITY) //auto incrememt 자동증가 기술 적용
        private Long id;
        
        //entity 입장에선 컬럼명
        private String name;
    }
    ```

* step01 - 단순 Test

    ```Java
    public static void step01() {
    	/* persistence.xml의 db설정 정보 기반으로 생성되는 객체
    	 * - db 접속, 관리
    	 * - entity 클래스 관리 (table 생성, 유지등)
    	 * - db접속 / sql 문장실행 (drop, create) - DDL
         * - EntityManager 객체들을 생성해서 제공해주는 핵심 API
    	 */
        EntityManagerFactory emf = Persistence.createEntityManagerFactory("jpaPU");

        /* EntityManager
         * - CRUD(Create, Read, Update, Delete) 작업용 API
         * - persist() : insert sql 메소드
         * 
         * EntityTransaction
         * - tx : insert/update/delete 문장만 tx와 연계
         * - 이미 존재하는 table의 데이터 추가, 수정, 삭제시에만 필요한 API
         * - EntityManager로부터 생성
         *  : 어떤 db, 어떤 table에 대한 정보를 보유한 객체로부터 생성해야만하기 때문
         * - begin() : tx 시작의미
         * - commit() : commit 영구 저장 sql 명령어
         * - rollback() : 복원 메소드
        */
        EntityManager em = emf.createEntityManager();
        EntityTransaction tx = em.getTransaction();

        tx.begin();
        Member m1 = new Member();
        m1.setName("연아");
        em.persist(m1);
        
        m1.setName("재석");
        
        tx.commit();

        em.close();
        emf.close();
    }
    ```

* step02 - find()/remove()

    ```Java
    public static void step02() {
    	//접속
    	EntityManagerFactory emf = Persistence.createEntityManagerFactory("jpaPU");
    	
    	//sql문장 실행해서 검색
    	EntityManager em = emf.createEntityManager();
    	EntityTransaction tx = em.getTransaction();
    	tx.begin();
    	    	
    	//SELECT * FROM member WHERE id = 1; 
    	//검색된 데이터값으로 Member 객체 생성
    	Member m = em.find(Member.class, 1L); //1은 int간주, 1L of 1l로 long
    	System.out.println(m);
    	
    	//수정 - tx 적용 필수
    	//첫번째 다른 값으로 수정 성공, 두번째 동일한 데이터값으로 수정 시도했으니 update 문장자체도 안 만들어짐
    	//UPDATE membet SET name = '이순신' WHERE id = 1;
    	m.setName("안유진");
    	System.out.println(m);
    	
    	em.remove(m); //delete
    	
    	//수정된 내용 실 반영 tx처리
    	//자원반납
    	tx.commit();
    	em.close();
    	emf.close();
    }
    ```
