```Jsp
<%
    request.setAttribute("rData1", "카페/나만의숍");

    session.setAttribute("sData2", "건강/가족");
	
	//ArrayList에 문자열들 저장

	all1.add("n8n");
	all1.add("art&tech");

    session.setAttribute("sData4", all2);

```

## 2. EL Tag

* 동등 비교 연산자, 리스트

    ```Html
    <table border="1">
        <tr>
            <td>non-EL</td>
            <td>EL</td>
        </tr>
        <tr>
            <td>1+3</td>
            <td>${1+3}</td>
        </tr>
        <tr>
            <td>'a' == 'a'</td>
            <td>${'a' == 'a'}</td>
        </tr>
        <tr>
            <td>'a' != 'a'</td>
            <td>${'a' != 'a'}</td>
        </tr>
        <tr>
            <td>request.getAttribute("rData1")</td>
            <td>${requestScope.rData1}</td>
        </tr>
        <tr>
            <td>session.getAttribute("sData1")</td>
            <td>${sessionScope.sData1}</td>
        </tr>
        <tr>
            <td>((ArrayList<String>) session.getAttribute("sData3")).get(0)</td>
            <td>${sessionScope.sData3[0]}</td>
        </tr>
    </table>
    ```

* sData4로 저장된 연아 이름만 출력

    ```Html
    <td>((ArrayList<People>) session.getAttribute("sData4")).get(0).getName()</td>
    <td>${sessionScope.sData4[0].name}</td>
    ```

    * `${sessionScope.sData4[0].name}` 코드가 작동하려면 People 클래스에 `public getName()` 메서드가 반드시 존재해야함 (EL은 필드에 직접 접근하는 것이 아니라 Getter를 호출)

* sData4로 세션에 저장된 ArrayList의 Peope들의 나이 비교를 해서 age가 50인 사람의 이름과 나이값 브라우저 출력

    ```Html
	<c:forEach items="${sessionScope.sData4}" var="people">
		<c:if test="${people.age == 50}">
			${people.name} - ${people.age}<br>
		</c:if>
	</c:forEach>
    ```

## 3. EL Tag의 NULL 처리 방식

* 로컬 변수는 선언지 자동 초기화를 진행하지 않음

* 선언만 한 경우, null도 아니고, 아무런 데이터를 가지고 있지 않음

* Java 예시

    ```Java
    // 변수가 초기화되지 않았을 가능성이 있어 컴파일 불가
    String value;
	System.out.println(value.charAt(1));
    out.println(value.charAt(1));

    // 컴파일은 성공하지만, 실행 시 'NullPointerException' 발생 및 중단
    String value = null; 
    System.out.println(value.charAt(1)); 
    out.println(value.charAt(1));
    ```

* EL Tag: null을 빈 문자열 ("")로 처리하여 화면에 출력하므로 공백 방지 로직이 간결함

    ```Html
    <%
    String value = null;
	out.println(value); // 출력: null
	request.setAttribute("rData2", value);
    %>
    <hr color="red" size="3">
	rData2가 null인 경우에는 "데이터가 없음" 출력 / 있을 경우 데이터 출력 (비교 적용) <br>
	ELtag의 null값 처리 비교 학습 : == / != / empty / not empty <br>
	1. ${requestScope.rData2} <br> <!-- 예외를 던지지 않고 무시 -->
	2. ${requestScope.rData2 == null} <br> <!-- true -->
	3. ${empty requestScope.rData2} <br> <!-- true -->
	4. ${not empty requestScope.rData2} <br> <!-- false -->
    ```

## 4. 이미지 및 내부 자원 경로 이슈

### 4.1 문제 발생 원인: Forward의 특징

* 상황: 서블릿에서 JSP로 forward 이동 시, 브라우저 주소창의 URL은 서블릿 경로 (.../fisa/dept)에 멈춰 있습니다.

* 현상: 브라우저는 현재 URL을 기준으로 상대 경로를 계산하므로, JSP 파일의 실제 위치와 상관없이 잘못된 경로에서 리소스를 찾게 됩니다.

* 구체적 경로 비교

    * 클라이언트가 보는 주소: http://localhost:8080/step04_CP/fisa/dept

    * 실제 리소스 위치: http://localhost:8080/step04_CP/deptallviewfinal.jsp

    * 잘못된 이미지 호출: http://localhost:8080/step04_CP/fisa/images/tablesetting.jpg

        * 브라우저가 /fisa/를 현재 폴더로 인식하여 그 하위의 images를 찾으려 함

### 4.2 해결 방법: Context Path 확보

* 핵심: 상대 경로 대신 서버의 Context Root부터 시작하는 절대 경로를 사용하여 경로 의존성을 제거합니다.

* 문법: `${pageContext.request.contextPath}`

    * 프로젝트명 (Context Root)이 바뀌어도 동적으로 대응 가능한 EL 내장 객체 문법입니다.

* 적용 예시

    ```Html
    <img src="${pageContext.request.contextPath}/images/tablesetting.jpg">

    <link rel="stylesheet" href="${pageContext.request.contextPath}/css/style.css">
    <a href="${pageContext.request.contextPath}/dept.html">메인으로 이동</a>
    ```
