# SpringBoot PageMove, Session and Cookie

## 1. Spring Framework

* 서버 설정의 수동화: 개발자나 운영자가 Apache Tomcat과 같은 외부 WAS를 직접 설치하고 `pom.xml`이나 별도의 설정을 통해 서버 환경을 구축해야 합니다.

* 프로젝트 구조의 일관성: 기존 Eclipse 웹 개발 구조와 유사하며, 파일 위치 (`WEB-INF/views` 등)가 엄격히 고정된 상태에서 라이브러리만 추가하여 구동되는 방식입니다.

## 2. SpringBoot

Spring Boot는 설정보다는 관례(Convention over Configuration)를 중시하며, 개발자가 인프라보다는 비즈니스 로직에 집중할 수 있는 구조를 제공합니다.

* 내장 서버 활용: 별도의 서버 설치 없이 내장된 Tomcat을 사용하여 즉시 실행이 가능하며, 필요에 따라 Jetty나 Undertow 등으로 서버 설정을 유연하게 변경할 수 있습니다.

* IDE 지원 및 플러그인: STS (Spring Tool Suite)는 기본적으로 HTML/CSS/JS 편집 기능을 제공하지만, 보다 편리한 웹 개발 (JSP, XML 편집 등)을 위해서는 마켓플레이스에서 `Eclipse Enterprise Java and Web Developer Tools` 플러그인 설치를 권장합니다.

* 정적 자원 (Static Resources) 관리

    * 경로: `src/main/resources/static`

    * 내용: 서버에서 가공이 필요 없는 HTML, CSS, JavaScript, 이미지 파일 등이 위치하며 브라우저가 직접 요청하여 실행합니다.

* 동적 자원 (JSP/Dynamic) 관리

    * `webapp/`: 일반적인 웹 애플리케이션의 자원들이 위치하는 전통적인 경로입니다.

    * `webapp/WEB-INF/`: 보안이 강화된 경로로, 브라우저가 직접 URL을 통해 접근할 수 없으며 오직 컨트롤러를 통해서만 접근 및 실행이 가능합니다.

## 3. 모든 Web Application Server (WAS)의 표준 스펙 구조

### 3.1 런타임 배포 구조 (Deployment Structure)

```Plain text
[Context Root] (프로젝트 접속 경로)
├── WEB-INF/                    # 외부 직접 접근 불가 보안 영역
│   ├── classes/                # 작성한 자바 소스가 컴파일된 *.class 파일 위치
│   ├── lib/                    # 프로젝트 실행에 필요한 외부 라이브러리 (*.jar)
│   └── views/                  # 컨트롤러를 통해 호출되는 JSP 파일 (위치는 설정에 따라 상이)
├── static/                     # 브라우저가 직접 접근하는 정적 파일 영역
│   ├── css/
│   └── js/
└── index.html                  # 메인 페이지
```

### 3.2 이클립스/STS 내부 배포 경로

```Plain text
[Eclipse Workspace]/.metadata/.plugins/org.eclipse.wst.server.core/tmp0/wtpwebapps/[Context명]
```

## 4. SpringBoot에서 JSP 개빌시 참고 사항

### 4.1 컨트롤러와 서블릿의 관계

* DispatcherServlet의 동작: 개발자가 작성한 Controller는 Spring의 핵심 서블릿인 DispatcherServlet에 의해 관리 및 호출됩니다. 내부적으로는 서블릿 컨테이너 환경 위에서 구동되어 클라이언트의 요청을 처리합니다.

* 핵심 어노테이션

    * `@Controller`: JSP와 같은 View를 반환하여 페이지를 이동시킬 때 사용합니다.

    * `@RestController`: 데이터를 JSON/XML 형태로 반환할 때 사용하며, JSP 페이지 이동에는 적합하지 않습니다.

### 4.2 JSP 개발 환경 구축

Spring Boot의 표준 프로젝트 구조에는 JSP 경로가 포함되어 있지 않으므로 직접 생성해야 합니다.

* `src/main/webapp`: 웹 자원의 최상위 루트 폴더로 직접 생성합니다.

* `src/main/webapp/WEB-INF`: 사용자가 URL로 직접 JSP에 접근하는 것을 막기 위한 보안 폴더입니다. 보통 이 아래에 views 폴더를 만들어 관리합니다.

### 4.3 필수 설정 및 라이브러리

JSP를 인식하고 실행하기 위해 설정 파일과 빌드 파일에 내용을 등록해야 합니다.

* application.properties (또는 yml) 설정

    ```ini
    spring.mvc.view.prefix=/WEB-INF/views/
    spring.mvc.view.suffix=.jsp
    ```

### 5.1 의존성 라이브러리 버전 매핑 원리

* 버전 관리 자동화: `build.gradle` 상단에 선언된 Spring Boot 플러그인 버전 (`id 'org.springframework.boot' version '...'`)에 따라 메인 라이브러리들의 버전이 결정됩니다.

```Html
<a href="step03">4. Spring API로 test.jsp로 Forward 이동</a>
```

### 6.2 페이지 이동 방식 비교 (Forward vs Redirect)

`MySubController.java`에서 구현된 각 방식의 동작 차이입니다.

* Forward (포워드): 서버 내부에서 이동하므로 URL이 변하지 않고, 요청 객체 (request)에 담긴 데이터가 유지됩니다.

    ```Java
    // ModelAndView 방식 (데이터 전달 가능)
    @RequestMapping(value = "step01", method = RequestMethod.GET)
    public ModelAndView step01() {
        ModelAndView mv = new ModelAndView();
        mv.addObject("name", "김연아"); // 데이터 저장
        mv.setViewName("ce1");        // /WEB-INF/views/ce1.jsp 매핑
        return mv; 
    }

    // String 방식 (단순 이동)
    @RequestMapping(value = "step03", method = RequestMethod.GET)
    public String step03() {
        return "forward:/test.jsp"; // 내부적으로 test.jsp 실행
    }
    ```

* Redirect (리다이렉트): 브라우저에게 새로운 주소로 다시 접속하라고 명령합니다. URL이 변경되며 기존 요청 객체는 소멸됩니다.

    ```Java
    @RequestMapping(value = "step02", method = RequestMethod.GET)
    public String step02() {
        // 새 요청이므로 데이터 저장 로직이 필요 없을 때 사용
        return "redirect:/test.jsp";
    }
    ```


* `ce1.jsp`

    ```Java
    <body>
        ce1.jsp - ${requestScope.name}
    </body>
    ```

### 6.3 세션 상태 추적 (State Tracking)

`MySubControllerTracking.java`에서 `@SessionAttributes`를 활용한 로그인 및 로그아웃 프로세스입니다.

* 세션 생성 (Login)

    ```Java
    @SessionAttributes({"id"}) // 세션으로 관리할 key 등록
    public class MySubControllerTracking {
        @RequestMapping(value = "/login", method = RequestMethod.GET)
        public String loginCheck(@RequestParam("id") String id, Model session) {
            session.addAttribute("id", id); // @SessionAttributes에 의해 세션 자동 저장
            return "redirect:/welcome.jsp"; // 로그인 후 주소 변경을 위해 리다이렉트
        }
    }
    ```

* 세션 활용 및 삭제 (Logout)

    ```Java
    @RequestMapping(value = "/logout", method = RequestMethod.GET)
    public String logout(SessionStatus status, @ModelAttribute("id") String id) {
        // @ModelAttribute를 통해 세션 데이터 확인 가능
        status.setComplete(); // @SessionAttributes에 등록된 데이터만 무효화
        return "redirect:/welcome.jsp";
    }
    ```

* `welcome.jsp`

    ```Java
    <body>
        세션 데이터 -${sessionScope.id}- <br>
        <hr>
        
        <button onclick="location.href='ce/logout'">로그아웃</button>
    </body>
    ```

### 6.4 데이터 자동 바인딩 및 출력

사용자 입력 데이터를 DTO로 변환하여 화면에 출력하는 과정입니다.

* 컨트롤러 (`MySubControllerTracking.java`): 쿼리 스트링의 이름과 DTO (Emp2)의 멤버 변수명이 일치하면, 기본 생성자 호출 후 Setter를 통해 값이 자동 주입됩니다.

    ```Java
    @RequestMapping(value = "/add", method = RequestMethod.POST)
    public ModelAndView add(Emp2 emp) { 
        ModelAndView mv = new ModelAndView();
        mv.addObject("emp", emp);
        mv.setViewName("emponeinfoview"); 
        return mv;
    }
    ```

* 결과 화면 (`emponeinfoview.jsp`)

    * EL 표현식: `${requestScope.emp}`를 통해 컨트롤러에서 보낸 객체를 출력합니다.

    ```Java
    <body>
        -${requestScope.emp}-
        <br> 이름: ${requestScope.emp.ename}
        <br> 지역: ${requestScope.loc}
    </body>
    ```

## 7. Spring API

### 7.1 ModelAndView

* 데이터 (Model)와 화면 (View) 정보를 한꺼번에 관리하는 스프링의 전통적인 API입니다.

* Model: 비즈니스 로직의 결과 데이터 (Domain 또는 객체)를 담습니다.

* View: 데이터를 출력할 대상 화면 (Presentation) 정보를 담습니다.

* 역할: 두 기능을 결합하여 JSP로 이동할 때 데이터 출력 및 제어권을 위임하는 핵심 브릿지 역할을 수행합니다.

* 필수 설정: `application.properties`에 ViewResolver 설정을 등록해야 합니다.

    * JSP 파일 위치 등록: prefix와 suffix 설정을 통해 파일의 경로와 확장자를 지정해야 합니다.

### 7.2 Model

컨트롤러에서 뷰(JSP)로 데이터를 전달하기 위해 사용하는 인터페이스입니다.

* `@SessionAttributes`와의 연동: 클래스 상단에 `@SessionAttributes("별칭")`를 선언하면, Model에 담긴 특정 객체가 세션 영역에 자동으로 저장됩니다.

* 목적: JSP에서 서버의 데이터를 취득하고 활용하기 위해 사용합니다.

* 세션 활용 - `HttpSession`과 유사한 역할을 수행하며, 세션에 등록된 데이터는 JSP에서 `${sessionScope.별칭}` 형식으로 접근하여 출력할 수 있습니다.

* 사용 위치: 컨트롤러 내 서비스 메서드의 파라미터 (Parameter) 영역에 선언합니다.

    * 동작 방식: 개발자가 직접 생성하는 것이 아니라, 스프링 컨테이너가 이미 생성된 객체를 메서드 호출 시점에 주입해 주는 방식입니다.

### 7.3 SessionStatus

`@SessionAttributes`를 통해 관리되는 세션 데이터의 상태를 제어하는 API입니다.

* 관리 대상: `@SessionAttributes({"세션 데이터 별칭"})`에 등록되어 현재 세션이 유지되고 있는 값들을 관리합니다.

* 사용 시점: 주로 로그아웃 로직이나 프로세스 완료 시점에서 특정 세션 데이터를 무효화할 때 사용합니다.

* `setComplete()`: 현재 컨트롤러에서 세션에 등록한 어트리뷰트들을 제거합니다.

    * 참고: `HttpSession`의 `invalidate()`가 세션 전체를 날린다면, `setComplete()`는 `@SessionAttributes`로 관리되는 특정 데이터들만 선별적으로 정리하는 기능으로 간주할 수 있습니다.

## 8. 주요 어노테이션

### 8.1 `@Controller`

Spring MVC 프로젝트의 근간이 되는 어노테이션으로, 사용자의 요청을 받아 화면 (View)을 응답하는 데 최적화되어 있습니다.

* 역할: 클래스를 Spring MVC 컨트롤러로 등록하며, 내부적으로는 `DispatcherServlet`에 의해 관리되는 서블릿 객체처럼 동작합니다.

* 권장 용도: JSP나 Thymeleaf와 같은 템플릿 엔진을 사용하여 웹 페이지를 이동시킬 때 주로 사용합니다.

* 메서드 반환 타입

    * ModelAndView: 데이터 (Model)와 이동할 화면 (View) 정보를 모두 포함하여 응답하는 전통적인 방식입니다.

    * String: 이동할 JSP 파일의 경로 (View Name)를 문자열로 반환하며, 데이터는 별도의 Model 객체에 담아 전달합니다.

### 8.2 `@RequestMapping(value = "url", method = RequestMethod.방식)`

요청 URL과 HTTP 전송 방식(GET, POST, PUT, DELETE 등)을 컨트롤러 메서드에 매핑합니다.

* 유연성: 클래스 레벨에 선언하여 공통 경로 (Prefix)를 설정하거나, 메서드 레벨에서 세부 경로를 설정할 수 있습니다.

* 참고: 최근에는 더 직관적인 `@GetMapping`, `@PostMapping` 등을 사용하는 추세입니다.

### 8.3 `@RestController`

데이터 중심의 RESTful API를 구축할 때 사용하는 어노테이션으로, 별도의 JSP 없이 데이터 자체를 응답합니다.

* 특징: `@Controller`와 `@ResponseBody`가 결합된 형태입니다. 모든 메서드는 객체를 반환할 때 자동으로 JSON 포맷으로 변환되어 응답 본문에 담깁니다.

* 메서드 반환 타입

    * DTO (객체): 단일 데이터를 JSON 객체(`{}`) 형태로 응답합니다.

    * List / Array: 다수의 데이터를 JSON 배열(`[]`) 형태로 응답합니다.

    * String: 텍스트 데이터나 단순 메시지를 직접 응답합니다.

### 8.4 `@GetMapping("url")` / `@PostMapping("url")`

`@RestController` 또는` @Controller` 내에서 특정 HTTP 메서드 요청을 간결하게 처리하기 위한 축약형 어노테이션입니다.

* GetMapping: 주로 데이터를 조회 할 때 사용하며 브라우저 주소창을 통한 접근이 가능합니다.

* PostMapping: 데이터를 생성하거나 보안이 필요한 정보를 전송할 때 사용합니다.

### 8.5 `@SessionAttributes({"세션 데이터 별칭"})`

특정 데이터를 세션 스코프에 저장하여 여러 요청 간에 데이터를 공유할 때 사용합니다.

* 선언 위치: 클래스 선언부 상단에 위치합니다.

* 동작 원리: Model API에 저장된 데이터 중 설정된 별칭과 일치하는 데이터가 있다면, 이를 자동으로 세션 (`HttpSession`) 영역에 복사하여 보관합니다.

* 주의: 별칭 등록이 누락되면 일반 Model 데이터로 취급되어 세션에 저장되지 않습니다.

### 8.6 `@ModelAttribute("세션 별칭")`

`@SessionAttributes`로 관리되는 세션 데이터를 메서드의 파라미터로 편리하게 가져올 때 사용합니다.

* 역할: 세션에 이미 저장된 데이터를 꺼내와 메서드 내에서 활용할 수 있게 해줍니다.

* 동작 방식: 내부적으로는 `(자식타입) session.getAttribute("별칭")`와 동일한 동작을 어노테이션으로 추상화한 것입니다.
