# SpringBoot DI

스프링 프레임워크의 핵심인 의존성 주입(DI)에 대해서 학습합니다.

* 실습 구조

    ```Plain text
    - Car.java
    - Engine.java

    Car는 Engine을 멤버 변수로 보유 : Has a 관계
    개발자 코드로 객체 생성하는 문법없이 설정으로만 개발 - properties 또는 어노테이션
    ```

    ```Plain text
    application.yml
        1. context명 : ce
        2. port : 80
    ```

* `application.yml`

    ```yaml
    spring:
      application:
        name: step01_basic
    server:
      port: 80
      servlet:
        context-path: /ce
    ```

## 1. 상식 및 참고 사항

* Has-a (포함 관계): 클래스가 다른 클래스의 인스턴스를 멤버 변수로 보유하는 관계입니다. (예: Car has an Engine)

* Is-a (상속 관계): 한 클래스가 다른 클래스의 특성을 이어받는 관계입니다. (예: Sedan is a Car)

## 2. 용어 암기 사항

### 2.1 Java Bean

데이터를 저장하고 전달하기 위한 가장 기본적인 자바 객체 형식입니다.

* 구조적 특징: DTO (Data Transfer Object)나 VO (Value Object)와 동일한 형태를 취합니다.

* 작성 규칙: 캡슐화를 위해 멤버 변수는 private으로 선언하며, 기본 생성자와 함께 Getter/Setter 메서드를 반드시 포함해야 합니다.

### 2.2 Spring Bean

스프링의 관리 감독을 받는 객체들을 의미합니다.

* 정의: 개발자가 직접 new로 생성하는 것이 아니라, 스프링 컨테이너에 의해 생성, 조립, 관리되는 객체입니다.

* 특징: 컨테이너가 생명 주기를 관리하므로, 필요한 곳에 언제든 주입 (DI)될 준비가 되어 있습니다.

### 2.3 Spring Container

스프링 빈들의 공장이자 관리소 역할을 수행합니다.

* 역할: 객체의 생성부터 의존성 주입, 설정 관리, 그리고 소멸까지의 전 과정을 총괄합니다.

* 유연성: 단순한 데이터 객체부터 복잡한 비즈니스 로직 클래스까지 모든 구조의 클래스를 스프링 빈으로 등록하여 관리할 수 있습니다.

### 2.4 Servlet Container

웹 애플리케이션의 핵심인 서블릿의 실행 환경을 제공합니다.

* 역할: 클라이언트의 요청에 따라 서블릿 객체를 생성, 실행, 소멸시키는 생명 주기를 관리합니다.

* 특징: 개발자는 비즈니스 로직에만 집중하며, 서블릿 객체를 직접 new 메서드로 생성하지 않습니다.

* 참고: 스프링 부트는 기본적으로 내장 Tomcat을 포함하고 있습니다.

### 2.5 Docker Container

애플리케이션과 그 실행 환경을 하나로 묶어 어디서나 동일하게 실행되도록 돕는 격리된 공간입니다.

* Docker Engine: 컨테이너를 생성하고 구동시키는 핵심 프로세스입니다.

* 활용 예시: Oracle Container를 통해 복잡한 설치 과정 없이 Oracle DB를 즉시 실행, 정지, 관리할 수 있습니다.

## 3. 주요 어노테이션

* `@RestController`

* `@GetMapping`

* `@Postmapping`

* `@Component`

    * `@Service`: 의미만 서비스 로직의 클래스, Component 기반으로 구동

    * `@Repository`: 의미만 DAO 로직의 클래스, Component 기반으로 구동

* `@Autowried`

## 4. 예제 코드

* `Car.java`

    ```Java
    package edu.fisa.ce.model.domain;

    import org.springframework.beans.factory.annotation.Autowired;
    import org.springframework.context.annotation.Scope;
    import org.springframework.stereotype.Component;

    @Component
    @Scope("prototype")
    public class Car {
        private String carName = "그랜저";
    //	@Autowired
        private Engine carEngine;
        
        public Car() {
            System.out.println("Car 생성자");
        }

        public String getCarName() {
            System.out.println("Car getCarName()");
            return carName;
        }

        public void setCarName(String carName) {
            System.out.println("Car setCarName()");
            this.carName = carName;
        }
        
        
        public Engine getCarEngine() {
            System.out.println("Car getCarEngine()");
            return carEngine;
        }

        @Autowired
        public void setCarEngine(Engine carEngine) {
            System.out.println("Car setCarEngine()");
            this.carEngine = carEngine;
        }

    }
    ```

## 5. 질문

### 5.1 생성자 실행 (객체 생성) 시점

* 애플리케이션 기동 및 컴포넌트 스캔: 서버 (Spring Boot)가 기동될 때 `@SpringBootApplication` 어노테이션을 기점으로 프로젝트 내의 모든 클래스를 스캔합니다.

    * Singleton 빈: 서버 기동 시 즉시 생성

    * Prototype 빈: 호출되는 시점에 생성자가 실행

* 환경 설정 로드: `application.yml` 파일의 설정값과 자바 코드 내의 설정 정보 (`@Configuration`)를 읽어 들여 메모리에 구성합니다.

* `@Component`: Spring Bean 등록 및 인스턴스화:

    * 스캔 과정에서 `@Component` (및 `@Service`, `@Controller` 등)가 선언된 클래스를 찾아 Spring Bean으로 등록합니다.

    * 이때 해당 클래스의 기본 생성자가 호출되며 객체가 실제로 생성 (인스턴스화)됩니다.

* `@Autowired`: 의존성 자동 주입:

    * 타입 매칭: 스프링 컨테이너에 등록된 빈들 중 타입이 일치하는 객체를 찾아 의존 객체를 자동으로 주입합니다.

    * 제약 사항: 주입받으려는 객체와 주입 대상 객체 모두 반드시 스프링 컨테이너가 관리하는 Spring Bean이어야 합니다.

    * 주입 방식의 세부 동작:

        * 필드 주입 (Field Injection): 변수 선언부에 선언하며, 스프링이 리플렉션을 통해 의존 객체를 직접 주입합니다. 내부적으로는 `Setter`를 통한 주입과 유사한 메커니즘으로 동작합니다.

        * 수정자 주입 (Setter Injection): `setXxx` 메서드 상단에 선언하며, 스프링이 해당 메서드를 직접 호출하여 의존성을 주입합니다.

### 5.2 Has a 관계의 객체 주입 시점 및 방식

* TestController와 Singleton Pattern

    * 서버 내부에서 컨트롤러는 Singleton으로 관리됩니다.

    * 단일 객체 서비스: 서버 기동 시 단 한 번만 생성되어 모든 클라이언트 요청을 처리합니다.

    * 재사용성: 컨트롤러가 멤버로 보유한 Car 객체 역시 이미 생성된 빈이 있다면 이를 그대로 재사용합니다.

    * 서블릿과의 관계: 서블릿 컨테이너 역시 서블릿을 단일 객체로 생성하여 운용하는 것과 동일합니다.

* `@Scope` 설정을 통한 제어

    * 만약 공유하지 않고 매번 새로운 객체를 사용하고 싶다면 스코프 (Scope) 설정을 변경해야 합니다.

    * singleton (기본값): 애플리케이션 전체에서 단 하나의 객체만 생성 및 공유합니다.

    * prototype: 주입 요청이 있을 때마다, 혹은 컨테이너에서 꺼낼 때마다 새로운 객체를 생성합니다.

* 참고: 계층형 아키텍처에서의 객체 관리

    * 실무적인 웹 서비스 구조 (View <-> Controller <-> Service <-> Repository <-> DB)에서는 효율성을 위해 객체 공유가 강제됩니다.

    * 강제적인 단일 객체 설정: 수만 명의 사용자가 동시에 접속하는 환경에서 요청마다 Service와 Repository 객체를 새로 생성하면 서버 메모리가 견디지 못합니다.

    * Stateless 설계: 단일 객체를 공유하기 때문에, 각 객체는 특정 사용자의 상태 정보를 멤버 변수에 저장해서는 안 됩니다. 오직 기능만을 수행하고 결과값은 즉시 반환해야 합니다.

### 5.3 Car의 Autowired 위치

* 필드 주입 (Field Injection)

    * 변수 선언구 상단에 어노테이션을 위치시키는 방식입니다.

    * 코드 위치: `private Engine engine;` 바로 위에 `@Autowired`를 작성합니다.

    * 동작 원리: 스프링 컨테이너가 리플렉션 기술을 사용하여 해당 필드에 의존 객체를 직접 주입합니다.

    * 사용자 정의 포인트: 변수 선언부에 위치할 경우, 스프링이 대리자 코드를 자동 생성하여 내부적으로는 `setXxx` 메서드를 호출하여 초기화하는 것과 유사한 방식으로 동작합니다.

* 수정자 주입 (Setter Injection)

    * `setEngine` 메서드 선언구 상단에 어노테이션을 위치시키는 방식입니다.

    * 코드 위치: `public void setEngine(Engine engine)` 메서드 위에 `@Autowired`를 작성합니다.

    * 동작 원리: 스프링이 해당 `setXxx` 메서드를 런타임에 직접 호출하여 의존 객체를 주입합니다.

    * 사용자 정의 포인트: 메서드 선언부에 위치할 경우, 스프링에 의해 해당 메서드가 명시적으로 호출됨으로써 주입이 완료됩니다.
