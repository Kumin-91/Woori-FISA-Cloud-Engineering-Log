# SpringBoot Basic

## 1. 주요 특징

* 독립 실행 가능: 웹 애플리케이션임에도 불구하고 별도의 WAS (Web Application Server) 설치 없이 자바의 main() 메서드만으로 실행 가능합니다.

* 내장 서블릿 컨테이너: Tomcat이 내장되어 있어 별도의 서버 설정이 필요 없으며, Spring Boot DevTools를 통해 코드 수정 시 실시간 리로드를 수행합니다.

* 스타터를 통한 자동 설정: 프로젝트 생성 시 필요한 의존성을 선택하는 것만으로 복잡한 XML 설정 없이도 라이브러리 세팅이 완료됩니다.

* 어노테이션 기반 추상화: 반복적인 설정 코드가 어노테이션으로 고도화되어 있어 개발자는 비즈니스 로직 구현에만 집중할 수 있습니다.

* 운영 편의성: 모니터링, 메트릭 측정 등 운영에 필요한 기능을 기본적으로 제공합니다.

* 결론: 설정에 소요되는 시간을 획기적으로 줄여 개발 속도가 빠르고, 환경에 구애받지 않는 독립적인 운영이 가능합니다.

## 2. 배포 방식의 변화: `*.war` vs. `*.jar`

전통적인 웹 방식과 Spring Boot의 가장 큰 외형적 차이는 빌드 결과물인 압축 확장자에 있습니다.

* `*.war` (Web Application Archive): Servlet & JSP 기반으로, 별도로 설치된 외장 WAS (Tomcat, WebLogic 등)에 배포하기 위한 표준 압축 방식입니다.

* `*.jar` (Java Archive): Spring Boot의 표준 방식으로, 내장 Tomcat을 포함하고 있어 `java -jar` 명령만으로 어디서든 즉시 실행 가능한 독립형 배포 방식입니다.

## 3. Spring Framework vs. Spring Boot 상세 비교

| 구분 | Spring Framework | Spring Boot |
| --- | --- | --- |
| 환경 설정 | 개발자가 직접 pom.xml, XML/Java 설정을 구성 | Starter와 Auto Configuration을 통해 개발 환경 자동 세팅 |
| 서블릿 서버 | 외부 Web Server를 별도 설치 및 등록 필요 | 내장 Tomcat을 사용하여 별도 설치 불필요 |
| 개발 생산성 | 코드 수정 시 서버 재배포 및 재실행 작업이 번거로움 | DevTools 등을 통해 실시간 자동 서버 재실행 지원 |
| 패키징 | `*.war` | `*.jar` (권장) 및 `*.war` |
| View 기술 | JSP 중심의 화면 렌더링 | REST API (JSP 사용은 제약이 많아 비권장) |

## 4. Spring Boot의 현대적 개발 지향점

* REST API 사용 권장: 화면을 직접 그리기보다 데이터를 주고받는 API 서버로서의 역할에 충실합니다.

* `@GetMapping`, `@PostMapping` 등 각 HTTP Method에 최적화된 전용 어노테이션 사용을 권장하여 코드 가독성을 높입니다.

* JSP 사용 지양: Spring Boot의 독립 실행형 `.jar` 방식에서는 JSP의 동작이 제한적이므로, 대신 Thymeleaf 같은 템플릿 엔진이나 React/Vue 같은 프론트엔드 프레임워크와의 협업을 지향합니다.

## 5. 코드 예시

```Java
package edu.fisa.ce.controller;

import java.util.ArrayList;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RestController;
import edu.fisa.ce.model.domain.Customer;

@RestController // @Controller + @ResponseBody: 모든 메서드의 반환값을 JSON/텍스트로 처리
public class TestController {

    // 1. 단순 문자열 반환 (GET 방식)
    // URL: http://localhost:8080/fisa1
    @GetMapping("fisa1")
    public String m1() {
        System.out.println("m1() 실행 - Server Console"); 
        return "연아 <별>"; // 클라이언트 브라우저에 문자열 그대로 응답
    }
    
    // 2. 동일 경로, 다른 HTTP Method (POST 방식)
    @PostMapping("fisa1")
    public String m2() {
        System.out.println("m2() 실행 - Server Console");
        return "연아2";
    }
    
    // 3. DTO 자동 바인딩 및 JSON 변환
    /*
        * [요청 시 데이터 바인딩]
            Query String의 Key(name, age)와 DTO의 멤버 변수명이 일치할 경우 
            Spring이 자동으로 객체를 생성하고 데이터를 주입합니다.
        * [응답 시 JSON 변환]
            반환 타입이 DTO일 경우, Jackson 라이브러리가 동작하여 
            객체를 JSON 포맷('{"name":"연아", "age":30}')으로 자동 변환해 응답합니다.
     */
    @PostMapping("fisa2")
    public Customer m3(Customer dto) {
        System.out.println("m3() 데이터 수신: " + dto);
        return dto; 
    }
    
    // 4. 컬렉션 반환 및 JSON 배열 응답
    /*
        ArrayList 반환 시 클라이언트에게는 [{}, {}] 형식의 
        JSON 배열(Array)로 응답되어 JavaScript에서 즉시 활용 가능합니다.
     */
    @GetMapping("fisa/all")
    public ArrayList<Customer> m4(){
        ArrayList<Customer> all = new ArrayList<>();
        all.add(new Customer("원영", 21));
        all.add(new Customer("유진", 22));
        return all;
    }
}
```
