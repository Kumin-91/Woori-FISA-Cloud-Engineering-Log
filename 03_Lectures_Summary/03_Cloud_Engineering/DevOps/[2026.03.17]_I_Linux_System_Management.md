## 1. Swap 메모리 비활성화

```bash
# 메모리 상태 확인
free -h

# swap 활성화 여부 확인
cat /proc/swaps

# swap 메모리 비활성화
sudo swapoff --all

# swap 활성화 여부 재확인
cat /proc/swaps

# 재부팅 후에도 swap 비활성화 유지
sudo nano /etc/fstab
# 해당 라인 주석 처리
# /swap.img     none    swap    sw      0      
```

## 3. 서비스 관리

```bash
# 서비스 상태 확인
sudo systemctl status <SERVICE_NAME>

# 서비스 시작
sudo systemctl start <SERVICE_NAME>

# 서비스 중지
sudo systemctl stop <SERVICE_NAME>

# 서비스 재시작
sudo systemctl restart <SERVICE_NAME>

# 서비스 설정 다시 적용
sudo systemctl reload <SERVICE_NAME>

# 서비스 자동 시작 설정
sudo systemctl enable <SERVICE_NAME>

# 서비스 자동 시작 해제
sudo systemctl disable <SERVICE_NAME>

# 서비스 실행 상태 확인
sudo systemctl is-active <SERVICE_NAME>

# 서비스 자동 시작 설정 확인
sudo systemctl is-enabled <SERVICE_NAME>

# 실행 중인 서비스 목록 확인
sudo systemctl list-units --type=service --state=running
```

## 5. 서비스 로그 확인

### 5.1 로그 파일 경로: `/var/log`

* `/var/log/syslog`: 시스템 로그

* `/var/log/dmesg`: 커널 메시지 로그

* `/var/log/auth.log`: 인증 로그

### 5.2 로그 레벨

| Level | Description |
| --- | --- |
| 0 | Emergency |
| 1 | Alert |
| 2 | Critical |
| 3 | Error |
| 4 | Warning |
| 5 | Notice |
| 6 | Informational |
| 7 | Debug |

### 5.3 로그 확인 명령어

```bash
# 서비스 로그 확인
sudo journalctl -u <SERVICE_NAME>

# 실시간 로그 확인
sudo journalctl -uf <SERVICE_NAME>

# 특정 레벨 이상의 로그 확인
sudo journalctl -p <LEVEL> -u <SERVICE_NAME>

# 특정 시간 이후의 로그 확인
sudo journalctl --since "YYYY-MM-DD HH:MM:SS"
sudo journalctl --since "30 minutes ago"

# 로그 데이터를 파일로 저장
sudo journalctl | tee <LOG_FILE_PATH>
```
### 5.4 미션

* 미션 1 : 운영 서버에서 **warning 이상 로그만 확인하여 문제 가능성을 탐지**

    ```bash
    sudo journalctl -p warning
    ```
    
* 미션 2 : 오늘 서버에서 발생한 모든 로그를 확인

    ```bash
    sudo journalctl --since "today"
    ```
    
* 미션 3 : [서비스 장애 분석] docker 서비스가 동작하지 않을 경우, docker 서비스 로그 확인

    ```bash
    sudo journalctl -u docker
    ```

* 미션 4 : [서비스 장애 분석] nginx 서비스에서 **database 키워드가 포함된 로그** 검색해야 할 경우

    ```bash
    sudo journalctl -u nginx -g  database
    ```
    
* 미션 5 : [로그 필터링] mysql 서비스 관련하여 30분동안 발생된 error 로그 검색

    ```bash
    sudo journalctl -u mysql --since "30 minutes ago" -p error
    ```

## 6. 사용자와 디렉토리 구조

* `#`: root 사용자

* `$`: 일반 사용자

### 6.1 root 사용자로 전환

```bash
# root 사용자로 전환 (root 홈 디렉토리로 이동)
sudo su -
sudo -i

# root 사용자로 전환 (현재 디렉토리 유지)
sudo su
```

### 6.2 디렉토리

| Directory | Description |
| --- | --- |
| `/` | 루트 디렉토리 |
| `/bin` | 시스템 기본 명령어 바이너리 |
| `/usr` | 사용자 프로그램 및 라이브러리 |
| `/etc` | 시스템 설정 파일 |
| `/var` | 가변 데이터 파일 (로그, 캐시 등) |
| `/home` | 사용자 홈 디렉토리 |
| `/root` | root 사용자 홈 디렉토리 |
| `/opt` | 추가 소프트웨어 패키지 |

## 7. 환경 변수

### 7.1 주요 환경 변수

| Variable | Description | Example |
| --- | --- | --- |
| `$HOME` | 사용자 홈 디렉토리 경로 | `/home/username` |
| `$PATH` | 실행 파일 검색 경로 목록 | `/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin` |
| `$USER` | 현재 로그인한 사용자 이름 | `username` |
| `$SHELL` | 현재 사용 중인 쉘 프로그램 경로 | `/bin/zsh` |
| `$LANG` | 시스템 언어 및 지역 설정 | `en_US.UTF-8` |

### 7.2 환경 변수 설정 구조: 시스템 전역 설정

* `/etc/environment`: 시스템 전체에 적용되는 환경 변수 설정 파일

* `/etc/profile`: 시스템 전체에 적용되는 로그인 쉘 환경 설정 파일

* `/etc/bash.bashrc`: 시스템 전체에 적용되는 bash 쉘 환경 설정 파일

### 7.3 환경 변수 설정 구조: 사용자별 설정

* `~/.profile`: 사용자별 로그인 쉘 환경 설정 파일 (`~/.bash_profile` 혹은 `~/.bash_login`이 존재하지 않을 때 사용)

* `~/.bashrc`: 사용자별 bash 쉘 환경 설정 파일

* `~/.bash_profile`: 사용자별 bash 로그인 쉘 환경 설정 파일

### 7.4 미션

### 7.5 JDK 설치 및 환경 변수 설정

```bash
# JDK 설치
sudo apt install openjdk-17-jdk

# JAVA_HOME 환경 변수 설정
nano ~/.zshrc
nano ~/.bashrc
# 파일에 다음 라인 추가
export JAVA_HOME="/usr/lib/jvm/java-17-openjdk-amd64"
export PATH=$PATH:$JAVA_HOME/bin

# 변경 사항 적용
source ~/.zshrc
source ~/.bashrc

# 환경 변수 확인
echo $JAVA_HOME
echo $PATH
java -version
```

## 8. 패키지 개요 및 관리

### 8.1 패키지 삭제 명령어

```bash
# 패키지 삭제
sudo apt remove <PACKAGE_NAME>

# 의존성 패키지까지 삭제
sudo apt autoremove --purge <PACKAGE_NAME>

# 불필요한 패키지 정리
sudo apt autoremove
```

### 8.2 APT 저장소 설정 및 주요 파일

* `/etc/apt/sources.list`: APT 패키지 저장소 목록 파일

* `/etc/apt/sources.list.d/`: 추가 저장소 목록 파일이 위치하는 디렉토리

    * `*.sources`, `*.list`: 추가 저장소 설정 파일

### 8.3 기본 사용법

```bash
# 설치된 패키지 목록 확인
sudo apt list --installed

# 패키지 검색
sudo apt search <PACKAGE_NAME>

# 패키지 상세 정보 확인
sudo apt show <PACKAGE_NAME>

# 설치된 패키지와 설정 파일 삭제
sudo apt purge <PACKAGE_NAME>

# 패키지 캐시 정리
sudo apt clean
```

## 10. Crontab

[Crontab Generator](https://crontab-generator.org/)

### 10.1 Simple Crontab

```bash
# Crontab 편집
crontab -e

# 아래에 다음과 같이 입력
* * * * * echo "$(date): 크론탭 실행 test" >> ~/cron_test.log

# 작업 실행 확인
ls -l ~/cron_test.log
tail -f ~/cron_test.log
cat ~/cron_test.log

# Crontab 작업 삭제
crontab -r

# Crontab 작업 목록 확인
crontab -l
```

### 10.2 Crontab 기본 명령어

```bash
# Crontab 편집
crontab -e

# Crontab 작업 목록 확인
crontab -l

# Crontab 작업 삭제
crontab -r

# 특정 사용자 Crontab 편집
sudo crontab -e -u <USERNAME>

# 특정 사용자 Crontab 작업 목록 확인
sudo crontab -l -u <USERNAME>

# 특정 사용자 Crontab 작업 삭제
sudo crontab -r -u <USERNAME>
```

### 10.3 미션

* pwd라는 리눅스 명령어로 file 위치 수정하기

    ```bash
    * * * * * echo "$(date): 크론탭 실행 test" >> $(pwd)/cron_test.log
    ```

    * 파일 생성 위치는 해당 user의 home 디렉토리 (현재 작업 디렉토리가 아님)

### 10.4 Crontab 시간 표현

```
*            *            *            *            *            작업내용
분(0-59)      시간(0-23)    일(1-31)　　   월(1-12)　　   요일(0-6)
```

| 기호 | 의미 |
| --- | --- |
| `@yearly`, `@annual` | 매년 1월 1일 00:00에 실행 |
| `@monthly` | 매월 1일 00:00에 실행 |
| `@weekly` | 매주 일요일 00:00에 실행 |
| `@daily`  | 매일 00:00에 실행 |
| `@hourly` | 매시간 00분에 실행 |

## 11. 미션

### 11.1 크론탭으로 자동화: 매일 새벽 4시에 docker 불필요한 자원 삭제

```
0 4 * * * echo "$(date): Docker 자원 정리 $(docker system prune -af)" >> ~/docker_cleanup.log
```

```

```

### 11.3 Cron 로그 확인 자동화 (정해진 시간에 기록)

```
0 4 * * * echo "$(date): Cron 로그" $(journalctl -u cron --since "24 hours ago") >> ~/cron_logs.log
```
