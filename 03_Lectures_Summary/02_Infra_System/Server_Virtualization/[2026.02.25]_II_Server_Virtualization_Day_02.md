## 5. Types of Provisioning

### 5.1 Thick Provisioning

* 읽기와 쓰기 속도는 빠르지만, 초기에는 전체 스토리지 공간이 할당되어 낭비가 발생할 수 있음

* **Lazy Zeroed:** 생성 시 전체 공간을 할당하지만, 데이터가 실제로 쓰이는 시점에 해당 블록을 0으로 초기화 (가장 일반적인 기본값)

* **Eager Zeroed:** 생성 시점에 전체 공간을 할당함과 동시에 모든 블록을 0으로 초기화 (생성 시간은 오래 걸리지만, I/O 성능이 가장 좋음)

### 5.2 Thin Provisioning

* 사용할 때마다 필요한 만큼의 스토리지를 할당하는 방식

* 초기에는 작은 크기로 시작하지만, 데이터가 추가됨에 따라 크기가 동적으로 증가하는 방식

* Fragmentation: 디스크 공간이 연속적이지 않게 할당되어 성능 저하가 발생할 수 있음

* Thin에서 Thick으로의 전환은 가능하지만, Thick에서 Thin으로 전환은 불가능 (Cloning 또는 Storage vMotion 필요)

## 6. Types of Virtual Network Adapters

* **E1000E:** Intel Gigabit Ethernet NIC를 소프트웨어로 에뮬레이션한 어댑터 (Up to 1Gbps)

* **VMXNET3:** 가상화 환경에 최적화된 고성능 반가상화 어댑터 (Up to 10Gbps)

* **Flexible:** VM이 부팅될 때 E1000E 또는 VMXNET3 중에서 자동으로 선택하는 어댑터 유형

* **SR-IOV (Single Root I/O Virtualization) pass-through**

    * 물리 NIC의 자원을 여러 가상 기능 (VF: Virtual Function)으로 분할하여 가상 머신에 직접 할당

    * AWS: Enhanced Networking, Azure: Accelerated Networking

## 7. Types of Virtual Networks

* **Bridge Network**

    * 가상 머신이 호스트의 네트워크 인터페이스를 공유하여 외부 네트워크와 통신할 수 있도록 하는 방식

    * 호스트와 가상 머신이 동일한 네트워크 세그먼트에 존재

* **NAT Network**

    * 가상의 NAT 라우터를 통해 가상 머신이 외부 네트워크와 통신할 수 있도록 하는 방식

    * 가상 머신이 호스트의 IP 주소를 사용하여 외부 네트워크와 통신하는 방식

    * 가상 머신은 자체적으로 IP 주소를 가지지만, 외부에서는 호스트의 IP 주소로 인식

    * 실습 VMware Workstation: 192.168.88.0/24

    * xxx.xxx.xxx.1은 호스트의 IP 주소로 사용

* **Host-only Network**

    * 가상의 스위치를 통해 가상 머신이 호스트와 통신할 수 있도록 하는 방식

    * 가상 머신이 호스트와만 통신할 수 있도록 하는 방식

    * 외부 네트워크와의 통신은 불가능

    * 실습 VMware Workstation: 192.168.11.0/24

    * xxx.xxx.xxx.1은 호스트의 IP 주소로 사용
