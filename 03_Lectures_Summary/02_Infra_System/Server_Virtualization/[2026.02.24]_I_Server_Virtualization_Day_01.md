## 1. Terminology

* **DC: Data Center** 

    * 24/7 IT 장비들을 안정적으로 운영하기 위한 시설

    * 데이터를 저장하고 관리하는 시설로 서버, 스토리지, 네트워크 장비 등이 포함

* **IDC: Internet Data Center**

* **NGDC: Next Generation Data Center**

* **ISP: Internet Service Provider**

* **CSP: Cloud Service Provider**

* **MSP: Managed Service Provider**

* **UPS: Uninterruptible Power Supply**

## 2. Silo-Based DC

### 2.1 독립적, 폐쇄적 구조 (Vertical Isolation)

* 사일로 (Silo, 곡물 저장소)처럼 각 자원이 서로 연결되지 않고 수직적으로 분리되어 운영되는 형태

* 부서나 서비스별로 인프라를 따로 구축하기 때문에 정보 공유나 협업이 어려움

### 2.2 자원의 개별 관리 및 물리적 배치

* 서버, 스토리지, 네트워크 장비가 용도별로 독립된 공간 (Rack 등)에 배치되어 운영

* 특정 서비스에 자원이 남고 다른 서비스는 부족해도 자원을 유연하게 빌려줄 수 없어 자원 효율성이 떨어짐

### 2.3 강한 종속성 (Hardware-OS-App Dependency)

* 어플리케이션이 특정 OS와 하드웨어 사양에 강하게 결합 되어 있어 다른 환경으로의 이전이 어려움

* 새로운 서비스를 배포하려면 하드웨어 구매부터 OS 설치까지 모든 과정을 수동으로 진행해야함

## 3. Virtualization

### 3.1 Definition

* **Virtualization:** 물리적인 특성을 제외하고 소프트웨어적으로 구현된 가상 환경에서 컴퓨팅 자원을 제공하는 기술

* **Guest OS**

    * 가상 머신 내부에서 실행되는 독립적인 운영 체제

    * Host OS나 다른 VM과 완전히 격리되어 운영되므로, 하나의 VM에 장애가 발생해도 다른 VM이나 물리 서버에 영향을 주지 않음

* **VM: Virtual Machine**

    * 물리적인 하드웨어 (CPU, RAM, Disk 등)를 소프트웨어적으로 에뮬레이션하여 구현한 가상 컴퓨터

    * 하드웨어를 추상화한 설정 파일과 데이터가 담긴 디스크 파일로 구성

* **Host OS:** 물리적 서버에 직접 설치되어 하드웨어를 제어하고 가상화 환경을 지원하는 운영 체제

* **Hypervisor**

    * 물리 하드웨어 자원을 가상 자원으로 변환하여 여러 Guest OS에 적절히 배분하는 소프트웨어 계층

    * ESXi, KVM, Xen Server, Hyper-V

* **IaC: Infrastructure as Code**

* **PPar (Physical Partitioning):** 물리 서버를 여러 개의 독립된 파티션으로 나누어 운영하는 방식

* **LPar (Logical Partitioning):** 물리 서버의 자원을 논리적으로 분할하여 여러 개의 가상 머신으로 운영하는 방식

### 3.2 Virtualization Main Functions

* **Sharing:** 물리적 자원을 여러 가상 머신이 공유하여 사용할 수 있도록 하는 기능

* **Aggregation:** 여러 물리적 자원을 하나의 가상 자원으로 묶어서 제공하는 기능

* **Emulation:** 없는 자원을 소프트웨어적으로 구현하여 제공하는 기능

* **Isolation:** 상위 레벨에서 하위 레벨을 격리하여 안정성을 높이는 기능

### 3.3 Typical Virtualization Architectures

* **Type 1 Hypervisor (Bare-Metal)**

    * 하이퍼바이저가 직접 물리적 서버에 설치되어 운영되는 구조

    * H/W → Hypervisor → Guest OS

    * 가상 디스크 파일 포맷 예시

        * ESXi (.vmdk), Hyper-V (.vhd, .vhdx), KVM (.qcow2)

* **Type 2 Hypervisor (Hosted)**

    * 하이퍼바이저가 일반 운영 체제 위에 설치되어 운영되는 구조

    * H/W → Host OS → Hypervisor → Guest OS

    * VMware Workstation, VirtualBox

* **.ovf: Open Virtualization Format:** 가상 머신의 구성과 디스크 이미지를 표준화된 형식으로 패키징하여 배포하는 파일 포맷

* **Nested Virtualization**

    * 가상 머신 내부에서 또 다른 하이퍼바이저를 실행하여 그 위에 가상 머신을 생성하는 기술

    * 예: 물리적 ESXi 호스트 위의 VM 내부에 또 다른 ESXi를 설치하거나 Hyper-V를 실행하는 방식

* **Containerization**

## 4. Software-Defined Data Center (SDDC)

* 모든 인프라가 가상화 되어 있고, 소프트웨어로 제어되는 데이터 센터

* **VMware Solutions:** vSphere (Compute), vSAN (Storage), NSX (Network)

* **On-Premises:** 기업이 자체적으로 (사내에) 구축한 데이터 센터 <-> Cloud (Off-Premises)

## 5. Cloud

* **Private Cloud:** 기업이 자체적으로 구축하여 운영하는 클라우드 환경

* **Public Cloud:** 외부 클라우드 서비스 제공업체가 인터넷을 통해 제공하는 클라우드 환경

* **Hybrid Cloud:** Private Cloud와 Public Cloud를 조합하여 사용하는 클라우드 환경

* **Multi-Cloud:** 여러 클라우드 서비스 제공업체의 서비스를 동시에 사용하는 클라우드 환경

## 6. vSphere Virtualization of Resources

### 6.1 vHW: Virtual Hardware

* **CPU Virtualization**

    * 가상 머신에 CPU 자원을 할당하여 실행

    * 실제 CPU의 코어 수 만큼 각각의 VM에 할당 가능
    
    * VM에 할당된 CPU 코어의 수의 합이 실제 CPU 코어 수보다 많을 수 있음

* **Physical and Virtualized Host Memory Usage**

    * **Over-Provisioning:** 가상 머신에 할당된 메모리 양이 실제 물리적 메모리 양보다 많은 경우

    * VM이 사용하는 메모리의 양이 실제 물리적 메모리 양보다 많아지면 시스템이 스왑을 사용하여 성능 저하가 발생할 수 있음

    * Server Sprawl: 가상 머신이 너무 많아져서 관리가 어려워지는 현상

* **Physical and Virtual Networking**

    * 하나의 물리적 NIC (Uplink)를 여러 가상 머신이 가상 스위치 (vSwitch)를 통해 공유하여 사용

    * **동일 호스트 내 통신 (VM-I → vSwitch → VM-II):** 물리적 NIC를 거치지 않으므로 외부 물리 방화벽에서 트래픽 검사 및 통제가 불가능함

    * **외부 경유 통신 (VM-I → 물리 NIC → 외부 스위치/방화벽 → 물리 NIC → VM-II):** 보안 정책 적용 등을 위해 의도적으로 외부 네트워크 장비를 경유하게 하는 방식 (Hairpinning)

* **Physical File Systems and Datastores**

    * **Datastore:** VMFS(Virtual Machine File System), NFS 등을 포맷하여 가상 머신 파일(.vmdk, .vmx 등)을 저장하는 논리적 스토리지 컨테이너

* **GPU Virtualization**

## 7. vSphere User Interfaces

* **DCUI: Direct Console User Interface:** ESXi 호스트의 물리적 콘솔 (모니터/키보드)에서 직접 접근하여 초기 설정 및 문제 해결을 수행하는 텍스트 기반 인터페이스

* **VMware Host Client:** 웹 브라우저를 통해 단일 ESXi 호스트에 직접 접속하여 관리하는 HTML5 기반 인터페이스

* **vSphere Client:** vCenter Server에 접속하여 여러 ESXi 호스트와 클러스터를 중앙 집중식으로 통합 관리하는 웹 인터페이스
