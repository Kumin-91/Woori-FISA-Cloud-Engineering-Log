## 1. Configuring and Managing Virtual Networks

### 1.1 물리 및 가상 인터페이스 계층

* **PNIC (Physical Network Interface Card)**

    * ESXi 호스트에 장착된 실제 하드웨어 네트워크 카드

    * VMNIC (Virtual Machine Network Interface Card)

        * ESXi 호스트에서 인식하는 물리 NIC의 식별자 (예: vmnic0, vmnic1)

        * Uplink로 사용

* **VNIC (Virtual Network Interface Card)**

    * VM에 할당된 가상 네트워크 카드

    * Guest OS에서는 이 장치를 실제 네트워크 카드로 인식 (E1000E, VMXNET3 등)

### 1.2 vSwitch 구성 요소 및 포트 그룹

* **vSwitch (Virtual Switch)**

    * ESXi 호스트 내부에서 VM과 VM, 혹은 VM과 물리 네트워크 사이의 프레임 전송을 처리

    * 상위 물리 스위치와 유기적으로 연결

* **VMkernel Port Group (관리 및 시스템 트래픽)**

    * ESXi 호스트 자체의 서비스 통신을 위한 포트 그룹

    * VMkernel Port: 호스트의 IP 주소가 할당되는 지점이며, 다음과 같은 핵심 기능을 수행

        * Management: 호스트 관리 및 vCenter 통신

        * vSphere vMotion: 가상 머신의 실시간 마이그레이션 전용 트래픽

        * Storage: iSCSI나 NFS 기반의 외부 스토리지 연결

* **VM Port Group (데이터 트래픽)**

    * 실제 가상 머신들이 네트워크에 연결되는 포트들의 집합

    * 사용자 트래픽이 흐르는 곳이며, VLAN을 통해 네트워크를 논리적으로 분리

* **Uplink Port (물리 연결부)**

    * 가상 스위치와 VMNIC를 연결하는 상단 포트

    * 가상 스위치 내부의 트래픽이 서버 밖의 물리 스위치로 나가는 유일한 출구

### 1.3 Virtual Switch 연결 규칙

* **NIC Teaming**

    * 하나의 vSwitch에 여러 개의 VMNIC 연결 가능

    * 대역폭 확장과 링크 이중화를 구현

* **1:N 매핑 제한**

    * 하나의 VMNIC은 동시에 여러 개의 가상 스위치에 연결 불가능

    * 물리 포트 하나는 오직 하나의 스위치에만 연결

* **스위치 간 격리**

    * 가상 스위치끼리는 직접적인 업링크 연결 불가능

    * 스위치 간 통신이 필요하다면 상위 물리 스위치를 거치거나 동일한 VLAN 설정을 공유

* **폐쇄형 네트워크**

    * Uplink Port가 없는 가상 스위치 구성도 가능

    * 외부망과는 단절되며, 동일 호스트 내 VM 간의 고립된 통신 환경을 제공

### 1.4 VLAN

* 가상 스위치에서도 표준 802.1Q 프로토콜을 사용하여 프레임별 VLAN 태그를 인식하고 트래픽을 논리적으로 분리

* 가상 스위치의 포트 그룹에 설정된 VLAN ID는 상위 물리 스위치의 해당 포트 설정과 반드시 일치

### 1.5 Virtual Access Layer

* 기존 물리 네트워크의 3계층 (Core-Distribution-Access) 하단에 가상화로 구현된 Virtual Access Layer가 추가되어 VM까지 네트워크 정책을 전달

* **Standard Switch**

    * 단일 ESXi 호스트에 종속되어 동작하는 가장 기본적인 스위치

    * 호스트별로 개별적인 관리가 필요하여 규모가 작은 환경에 적합

* **Distributed Switch**

    * vCenter Server를 통해 여러 ESXi 호스트의 가상 스위치를 하나의 논리적 스위치로 통합 관리

    * 네트워크 설정의 일관성을 유지하고 vMotion 시에도 네트워크 상태 정보를 보존하는 고도의 관리 기능을 제공

## 2. Configuring Standard Switch Policies

### 2.1 Security Policies

* **Promiscuous mode:** VM이 자신에게 전달되지 않는 패킷도 수신할 수 있는지 여부 (네트워크 모니터링/스니핑 도구 사용 시 필요)

* **MAC address changes:** VM의 Guest OS에서 MAC 주소를 임의로 변경했을 때, 변경된 MAC 주소로 들어오는 (Inbound) 트래픽을 허용할지 여부

* **Forged transmits:** VM의 Guest OS에서 MAC 주소를 임의로 변경했을 때, 변경된 MAC 주소로 나가는 (Outbound) 트래픽을 허용할지 여부

* **Security Policy 적용 범위**

    * Port Group 단위 (최소 단위)로 설정 가능

    * vSwitch에 적용 가능

### 2.2 Traffic-Shaping Policies

* **Standard Switch의 한계:** 가상 머신에서 외부로 나가는 **Outbound (Egress) 트래픽에만 적용 가능** (Inbound 트래픽 제어는 Distributed Switch에서만 지원)

* **Average Bandwidth**

    * 장기적으로 허용되는 초당 평균 트래픽 양

    * kbit/s

    * 평상시 유지되는 네트워크의 기본 속도 제한선

* **Peak Bandwidth**

    * 트래픽에 여유가 있을 때 (Burst 상황) 일시적으로 허용되는 최대 속도

    * kbit/s

    * 반드시 평균 대역폭보다 크거나 같아야 함

* **Burst Size**

    * 최대 대역폭 (Peak)으로 전송할 수 있는 일시적인 데이터의 총량

    * 얼마나 오랫동안 혹은 얼마나 많은 양을 고속으로 보낼 수 있는가를 결정하는 데이터의 총량

* **Traffic Shaping 동작 원리**

    * 트래픽이 갑자기 몰릴 때, 가상 스위치는 Average Bandwidth를 넘어 Peak Bandwidth까지 대역폭을 일시적으로 허용

    * Burst Size를 모두 사용하고 나면, 아무리 트래픽이 많아도 속도는 다시 Average Bandwidth로 강제 제한

### 2.3 NIC Teaming and Failover Policies

* **Loop 방지를 위한 규칙**

    * STP: Spanning Tree Protocol에 참여하지 않음

    * Uplink Port를 통해서 들어온 트래픽은 다시 Uplink Port로 전송하지 않음

    * vSwitch가 전송한 트래픽이 다시 Uplink Port로 들어오면, 해당 트래픽은 스위치 내부에서 폐기

* MAC Address Learning 과정이 필요하지 않음 → VM이 생성될 때 MAC Address와 Port가 매핑되어 관리되기 때문

* **Load Balancing Method: Originating Virtual Port ID (Default)**

    * VM이 연결된 가상 포트에 따라 트래픽이 특정 Uplink Port로 라우팅

    * VM이 연결된 포트가 변경되지 않는 한, 트래픽은 항상 같은 Uplink Port를 통해 나감

    * VM이 재부팅되면, 다른 Uplink Port로 트래픽이 나갈 수 있음

    * Uplink Port의 대역폭이 트래픽의 최대 속도를 제한

* **Load Balancing Method: Source MAC Hash**

    * VM의 MAC 주소를 해싱하여 트래픽이 특정 Uplink Port로 라우팅

    * VM이 재부팅되어도, 같은 MAC 주소를 사용한다면 트래픽은 항상 같은 Uplink Port로 나감

    * 특정 Uplink Port로 트래픽이 몰릴 수 있음

    * Uplink Port의 대역폭이 트래픽의 최대 속도를 제한

* **Load Balancing Method: Source and Destination IP Hash**

    * VM의 IP 주소와 목적지 IP 주소를 해싱하여 트래픽이 특정 Uplink Port로 라우팅

    * Destination IP에 따라 트래픽이 다른 Uplink Port로 나갈 수 있음

    * 여러 개의 Uplink Port로 트래픽이 분산될 수 있음

    * Physical Switch에서 Link Aggregation (LACP) 설정이 필요

* **Active/Standby Failover**

    * Failover: Active Uplink Port가 실패하면, Standby Uplink Port가 자동으로 활성화되어 트래픽이 나감

    * Failback: Active Uplink Port가 복구되면, 다시 Active Uplink Port로 트래픽이 나감

        * Default: Enabled

        * 중요한 서비스의 경우 Disabled로 설정 권장

    * 대역폭은 Active Uplink Port의 대역폭으로 제한

    * Uplink Port의 속도가 다른 경우 사용 (예: 40Gbps + 10Gbps)

        * Active/Active로 구성하면, 40Gbps Uplink Port로 트래픽이 몰릴 수 있기 때문

## 4. Storage Concepts

### 4.1 Datastore

* VM 및 Object를 저장하는 논리적 컨테이너

* Object: VM의 구성 파일, 가상 디스크 파일, 스냅샷 파일 등

### 4.2 Datastore Types

* **VMFS (Virtual Machine File System)**

    * Block Storage 기반의 고성능 파일 시스템

    * 여러 ESXi 호스트에서 동시에 접근 가능

    * 여러 개의 하드 디스크를 하나의 논리적 볼륨으로 묶어서 사용할 수 있음

    * Cluster File System (Parallel File System)

* **NFS (Network File System)**

    * File Storage 기반의 네트워크 공유 스토리지

    * ESXi 호스트가 NFS 클라이언트가 되어 외부 NFS 서버의 디렉토리를 마운트하여 사용

* **vSAN (Virtual SAN)**

    * ESXi 호스트들의 로컬 디스크를 묶어서 하나의 거대한 공유 스토리지 풀로 만드는 소프트웨어 정의 스토리지 (SDS: Software-Defined Storage)

* **vSphere Virtual Volumes (vVols)**

    * 외장 스토리지의 LUN 단위 관리가 아닌, VM 단위로 스토리지 정책을 할당하고 세밀하게 관리할 수 있게 해주는 기술

### 5.2 Configure NFS Server on Linux-01 (Workstation)

#### 1. Assign IP Address

```Bash
# IP 및 서브넷 마스크 설정
sudo nmcli connection modify ens192 ipv4.addresses 172.16.10.3/24

# 게이트웨이 설정
sudo nmcli connection modify ens192 ipv4.gateway 172.16.10.1

# DNS 설정
sudo nmcli connection modify ens192 ipv4.dns 172.16.10.2

# 수동 모드로 변경
sudo nmcli connection modify ens192 ipv4.method manual

# 변경 사항 적용
sudo nmcli connection up ens192
```

#### 2. Install NFS Server

```Bash
sudo dnf install nfs-utils -y
```

#### 3. Configure NFS Exports

```Bash
sudo mkdir -p /srv/nfs_share
sudo chown -R nobody:nobody /srv/nfs_share
sudo chmod 777 /srv/nfs_share

# /etc/exports 파일에 아래 내용 추가
/srv/nfs_share  172.16.10.0/24(rw,sync,no_root_squash)
```

#### 4. Start NFS Server

```Bash
sudo systemctl enable --now nfs-server
sudo firewall-cmd --permanent --add-service=nfs
sudo firewall-cmd --permanent --add-service=rpc-bind
sudo firewall-cmd --permanent --add-service=mountd
sudo firewall-cmd --reload
```
