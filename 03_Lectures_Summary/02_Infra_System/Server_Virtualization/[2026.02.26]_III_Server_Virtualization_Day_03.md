## 1. vCenter & VCSA

* **VCSA: vCenter Server Appliance**

    * Photon OS 기반의 가상 어플라이언스

    * Photon OS: VMware가 직접 만든 리눅스로, 보안과 부팅 속도에 최적화되어 있어 관리 효율이 매우 높음

    * PostgreSQL: vCenter 내부의 모든 설정, 이벤트, 성능 로그를 저장하는 엔진

## 2. Communication between ESXi and vCenter Server

* **Flow:** vSphere Client → vpxd (vCenter) → vpxa (ESXi Agent) → hostd (ESXi Daemon) → VM

* **hostd**

    * ESXi 호스트에서 실행되는 데몬

    * 사용자 요청과 웹 클라이언트를 통해 ESXi 호스트와 통신하는 역할 (VM 관리, 리소스 모니터링 등)

    * 사용자 → VMware Host Client

* **vpxa (Virtual Provisioning X Agent)**

    * ESXi 호스트에서 실행되는 에이전트

    * vCenter와 ESXi 호스트 간의 통신을 담당하는 에이전트 (vCenter의 명령을 받아 hostd로 전달)

* **vpxd (Virtual Provisioning X Daemon)**

    * vCenter에서 실행되는 데몬

    * vCenter의 주요 기능을 담당 (호스트 관리, VM 관리, 리소스 할당 등)

    * 사용자 → vSphere Client → vpxd

* **Orphaned VM:** ESXi에 직접 접속해서 VM을 삭제한 경우, vCenter Database에는 존재하지만 실제로는 존재하지 않는 VM (또는 데이터스토어에서 VM 파일이 삭제되었으나 인벤토리에 남아있는 경우)

### 4.5 Step V: Setting up Licensing, Datacenter, Host and Account

#### 1. Licensing

* 설치 직후에는 60일간 모든 기능을 사용할 수 있는 Evaluation Mode로 동작

* 설정 경로: Menu → Administration → Licensing → Assets

* 구입한 라이선스 키를 vCenter에 등록한 후, 각 ESXi 호스트나 vCenter Server 인스턴스에 할당해야 기능 제한 없이 사용 가능

#### 2. Datacenter

* 인벤토리의 최상위 논리적 컨테이너로, 호스트, 네트워크, 스토리지를 하나로 묶는 단위

* 지리적 위치나 부서 단위로 생성하며, 클러스터를 만들기 위한 필수 단계

* vCenter 아이콘 우클릭 → New Datacenter → 이름 지정 (예: Common-DC)

#### 3. Host

* ESXi 호스트를 vCenter에 등록하면 호스트에 vpxa 에이전트가 설치되며 통신이 시작

1. 데이터센터 우클릭 → Add Host

2. 호스트의 IP 주소 또는 FQDN 입력

3. 관리자 계정과 패스워드 입력

4. 보안 인증서 확인 및 수락

#### 4. Account

* vCenter의 기본 인증 도메인은 vsphere.local이며, 관리자 계정은 administrator@vsphere.local

    * 실습 운영 환경 도메인은 vcsa.joone.fisa로 설정했으므로, 관리자 계정은 administrator@vcsa.joone.fisa

* 실무에서는 사내 AD: Active Directory와 연동하여 기존 사번 계정으로 로그인할 수 있도록 설정

* 특정 사용자나 그룹에 Role을 부여하여, 인벤토리 객체 (VM, Host 등)에 대한 제어 권한을 최종 확정

## 5. Inventory

* **Hosts and Clusters:** 물리적 서버 (Host)와 그들의 집합 (Cluster), 리소스 풀을 관리

* **VMs and Templates:** 가상 머신과 배포용 템플릿을 중심으로 관리

* **Storage:** 데이터스토어와 스토리지 정책을 관리하며, 어떤 VM이 어떤 저장소를 쓰는지 확인

* **Networking:** 표준 스위치 및 분산 스위치, 포트 그룹 등 네트워크 자원을 관리

## 6. Roles and Permissions

### 6.1 Concepts

* **Object:** 권한 적용의 대상이 되는 개체 (예: Datacenter, Cluster, Host, VM, Datastore 등)

* **Privilege:** 개별적인 행동 단위 (예: VM Power On, VM Power Off, VM Monitor 등)

* **Role:** 관리 편의를 위해 여러 Privilege를 묶어놓은 집합체 (예: Admin, Read-only 등)

* **Permission:** User/Group + Role + Object가 결합된 최종 상태

### 6.2 Conflict Resolution

* **User > Group:** 동일한 객체에 사용자 개인 권한과 그룹 권한이 동시에 걸려 있다면, 개별 사용자 권한이 우선

* **Child > Parent:** 하위 객체에 설정된 권한이 상위 객체의 권한을 덮어씀 (예: 데이터센터에는 읽기 전용이지만, 특정 VM에는 관리자 권한이 있다면 해당 VM은 관리 가능)

* **Specific > General:** 더 구체적으로 지정된 권한이 포괄적인 권한보다 우선 적용 (예: 특정 VM에 설정된 권한이 상위 폴더에 설정된 권한보다 우선)

## 7. Backing up and Restoring

### 7.1 VAMI: vCenter Server Appliance Management Interface

* `https://vcsa.joone.fisa:5480`

* Photon OS 레벨의 관리 인터페이스로, NTP 설정, 네트워킹, 업데이트, 그리고 파일 기반 백업을 수행

### 7.2 File-Based Backup

* vCenter의 설정값과 PostgreSQL 데이터베이스 정보를 파일 형태로 추출하여 저장

* 지원 프로토콜: FTP, SFTP, HTTP(S), NFS, SMB 등 다양한 외부 저장소로 스케줄 백업이 가능

### 7.3 Image-Based Backup

* VADP: vSphere Storage APIs - Data Protection을 사용하여 vCenter VM 자체를 통째로 스냅샷 기반 백업하는 방식
