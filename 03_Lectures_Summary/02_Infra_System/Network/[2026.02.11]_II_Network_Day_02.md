## 1. TCP: Transmission Control Protocol

* **Connection-Oriented Protocol**

    * 신뢰성 있는 데이터 전송 보장

    * 상대방이 패킷을 잘 받았는지, 순서대로 도착했는지 확인

* **Three-Way Handshake**

    * SYN: 연결 요청

    * SYN/ACK: 응답 확인

    * ACK: 연결 성립 확인

* **SYN Flooding Attack**

    * 공격자가 대량의 SYN 패킷을 보내 서버의 자원을 고갈시키는 공격

    * DoS, 여러 PC를 이용한 DDoS 공격으로 확장 가능

* **Flow Control**

    * 송신자와 수신자 간의 데이터 전송 속도를 조절

* **Sliding Window**

    * 송신자와 수신자가 서로의 처리 속도에 맞춰 데이터를 주고받도록 조절

    * 수신자가 처리할 수 있는 만큼의 데이터만 보내도록 함

* **Four-Way Handshake**

    * FIN: 연결 종료 요청

    * ACK: 종료 요청 확인

    * FIN: 종료 요청

    * ACK: 종료 확인

## 2. UDP: User Datagram Protocol

* **Best-Effort Delivery**

    * 신뢰성 없는 데이터 전송

    * 패킷이 손실되거나 순서가 바뀌어도 재전송하지 않음

## 3. DCB: Data Center Bridge

* **Lossless Ethernet:** 데이터 센터 내에서 손실 없는 이더넷 통신을 구현하기 위한 기술

## 4. Types of Communication

* **Unicast:** 1:1 통신

* **Multicast:** 1:N 통신 (네트워크 내 모든 장치가 아닌 특정 그룹 대상)

* **Broadcast:** 1:ALL 통신 (네트워크 내 모든 장치 대상)

## 5. Duplex Communication

* **Full Duplex:** 양방향 통신, 동시에 통신 가능

* **Half Duplex:** 양방향 통신은 가능하지만, 동시에 주고받을 수는 없는 방식

* **Simplex (Unidirectional):** 단방향 통신, 한쪽 방향으로만 데이터 전송 가능

    * GPS 처럼 수신자가 송신자에게 데이터를 보낼 필요가 없는 경우에 사용
    
    * 원전 처럼 보안상 이유로 한쪽 방향으로만 데이터가 흐르는 경우에 사용

## 7. IP Address

* **IPv4**

    * 10진수 32비트 주소 체계
    
    * 4개의 옥텟 (8비트)으로 구성
    
    * 각 옥텟은 0-255 범위 값 가지고 점 (`.`)으로 구분

* **IPv6**

    * 16진수 128비트 주소 체계
    
    * 8개의 블록 (16비트)으로 구성
    
    * 각 블록은 0-FFFF 범위 값 가지고 콜론 (`:`)으로 구분

* **MTU: Maximum Transmission Unit**

    * 네트워크에서 한 번에 전송할 수 있는 최대 데이터 크기

    * 일반적으로 이더넷의 MTU는 1500 바이트

    * Jumbo Frame: MTU가 1500 바이트보다 큰 프레임

* **Fragmentation**

    * MTU보다 큰 패킷을 여러 개의 작은 조각으로 나누어 전송하는 과정

    * 수신 측에서 다시 원래의 패킷으로 재조립

* **TTL: Time To Live**

    * 패킷이 네트워크를 통해 전달될 수 있는 최대 홉 수

    * 홉: 패킷이 라우터를 통과할 때마다 TTL 값이 1씩 감소, 1초 이상 경과할 때마다 TTL 값이 1씩 감소

    * TTL 값이 0이 되면 패킷은 폐기되어 무한 루프 방지

## 8. IPv4 Address Classes & Subnet Masks

* **Subnet Mask:** IP 주소를 네트워크 부분과 호스트 부분으로 나누는 데 사용되는 32비트 마스크

    * 네트워크 부분을 식별하는 비트는 1, 호스트 부분을 식별하는 비트는 0으로 설정

    * 예시: 255.128.0.0 (/9)

* **Reserved IP Addresses**

    * **0.0.0.0/8: 현재 네트워크 주소로 예약**

        * 0.0.0.0/0: 라우팅 테이블에서 기본 경로로 사용

    * **127.0.0.0/8은 루프백 주소로 예약**

        * 127.0.0.1 (localhost): 일반적으로 자기 자신을 가리키는 주소로 사용

* **Network Classes**

    * **A Class**

        * 첫 옥텟 범위: 1-126

        * 기본 서브넷 마스크: 255.0.0.0 (/8)

    * **B Class**

        * 첫 옥텟 범위: 128-191

        * 기본 서브넷 마스크: 255.255.0.0 (/16)

    * **C Class**

        * 첫 옥텟 범위: 192-223

        * 기본 서브넷 마스크: 255.255.255.0 (/24)

    * **D Class:** 멀티캐스트 주소 (224-239)

    * **E Class:** 실험적 용도 (240-255)

* **Default Gateway:** 네트워크 외부로 나가는 트래픽을 라우팅하는 데 사용되는 라우터의 IP 주소

* **Subnetting:** 하나의 네트워크를 더 작은 범위의 서브 네트워크로 나누는 과정

## 9. CIDR: Classless Inter-Domain Routing

* IP 주소를 더 유연하게 할당하고 라우팅하기 위한 방법

* 현대의 네트워크에서는 클래스 기반 주소 체계를 사용하지 않고 CIDR 표기법을 사용하여 서브넷을 정의

* 첫번째 IP 주소는 네트워크 주소 (호스트 부분이 모두 0), 마지막 IP 주소는 브로드캐스트 주소 (호스트 부분이 모두 1)로 예약되어 사용 불가

* **Broadcast Domain:** 브로드캐스트 패킷이 도달할 수 있는 네트워크 영역

* **Prefix Length:** CIDR 표기법에서 네트워크 부분을 나타내는 비트 수

## 10. FLSM: Fixed Length Subnet Mask

* 모든 서브넷이 동일한 서브넷 마스크를 가지는 방식

* **Q.**

    * IP 주소: 202.147.10.0

    * Subnet Mask: 255.255.255.0 (C Class)
    
    * 6개의 네트워크로 만들어주세요! (강의실 4개, 사무실 1개, 여유분 1개)

* **A.**

    * /24 → /25 (2^1 = 2개 Subnet 생성 가능, 부족)

    * /25 → /26 (2^2 = 4개 Subnet 생성 가능, 부족)

    * /24 → /27 (2^3 = 8개 Subnet 생성 가능, 충분)

    * $\therefore Subnet Mask: 255.255.255.224 (/27)$

        * Subnet I: 202.147.10.0 - 202.147.10.31

        * Subnet II: 202.147.10.32 - 202.147.10.63

        * Subnet III: 202.147.10.64 - 202.147.10.95

        * Subnet IV: 202.147.10.96 - 202.147.10.127

        * Subnet V: 202.147.10.128 - 202.147.10.159

        * Subnet VI: 202.147.10.160 - 202.147.10.191

        * Subnet VII: 202.147.10.192 - 202.147.10.223

        * Subnet VIII: 202.147.10.224 - 202.147.10.255

## 11. VLSM: Variable Length Subnet Mask

* 서로 다른 서브넷이 서로 다른 서브넷 마스크를 가지는 방식

* **Super Netting:** 여러 개의 작은 네트워크를 하나의 큰 네트워크로 합치는 과정

## 12. Private IP Address

* **Reference: IETF RFC 1918**

* 인터넷에 직접 연결되지 않는 내부 네트워크에서 사용하기 위해 예약된 IP 주소 범위

* 이외의 IP 주소는 Public IP Address로 간주되어 인터넷에서 직접 라우팅 가능

* **Private IP Ranges**

    * **A Class:** 10.0.0.0/8 - 10.0.0.0 - 10.255.255.255

    * **B Class:** 172.16.0.0/12 - 172.16.0.0 - 172.31.255.255

    * **C Class:** 192.168.0.0/16 - 192.168.0.0 - 192.168.255.255

## 13. NAT: Network Address Translation

* **Static NAT:** Private IP 주소와 Public IP 주소를 1:1로 매핑하여 고정된 변환을 제공하는 방식

* **NAT: Network Address Translation:** Private IP 주소를 Public IP 주소로 변환하여 인터넷과 통신할 수 있도록 하는 기술

* **NAT Overload / PAT: Port Address Translation:** 하나의 Public IP 주소를 여러 Private IP 주소와 포트 번호로 매핑하여 다수의 장치가 하나의 Public IP 주소를 공유할 수 있도록 하는 방식

* **SNAT: Source NAT:** 출발지 주소 변환 (Private IP 주소에서 Public IP 주소로의 변환만 수행하는 방식)

* **DNAT: Destination NAT:** 목적지 주소 변환 (Public IP 주소에서 Private IP 주소로의 변환만 수행하는 방식)

* **장점**

    * Private IP 주소를 사용하여 내부 네트워크의 보안을 강화

    * Public IP 주소의 수요를 줄여 비용 절감
